## Реализовано

- Аудит и архитектура. Основной стек сохранён.
- Постоянная SQLite-база: школы, аккаунты, роли, сессии, курсы/модули/уроки, задания, группы, назначения, попытки и черновики.
- Регистрация школы, вход/выход, scrypt, серверные сессии, восстановление администратора одноразовым кодом, сброс паролей участников, отзыв сессий, отключение доступа.
- Серверная изоляция школ, проверка связанных объектов, проверка роли и назначения перед доступом ученика.
- Desktop-интерфейс от 1280 px: обзор, курсы, редактор структуры, группы, участники, результаты.
- Шестишаговый конструктор: описание/цель, теория/инструкция/подсказки, стартовый код, тесты, интерактивный предпросмотр, публикация. Черновики, дублирование, редактирование, снятие публикации, порядок модулей/уроков/заданий, копирование курсов.
- Проверка вывода, нескольких входов/выходов и ручная оценка. Скрытые тесты не передаются ученику. Различаются ошибки исполнения, неправильные ответы, инфраструктурные ошибки и ожидание ручной проверки.
- Редактор ученика с теорией, подсказками, консолью, пробным запуском, серверным автосохранением и историей попыток.
- Прогресс и отчёты рассчитываются по сохранённым назначениям и попыткам. Фиктивной статистики нет.
- Исходный курс и Blockly доступны по `?legacy=1`.
- AI выключен независимо от переменных окружения в новом и прежнем API; клиентские флаги выключены. Код сохранён для будущего возврата.
- Сценарий демонстрационных данных создаёт реальные записи, без выдуманных результатов.

## Ограничения первого пилота

- Python исполняется существующим учебным интерпретатором, не CPython. Нет импортов, классов и сторонних библиотек. Отдельный процесс имеет дедлайн, ограничение heap, вывода, операций и параллелизма. Для полного Python нужен отдельный контейнерный сервис; небезопасный запуск системного Python не добавлялся.
- Blockly не редактируется новым конструктором; сохранён исходный курс. Его локальный прогресс не смешивается с B2B.
- SQLite, лимиты и сервер рассчитаны на один экземпляр. Для большого SaaS нужны PostgreSQL, очередь исполнений и нагрузочные испытания.
- Восстановление учеников выполняет преподаватель; администратор использует recovery-код. Email не собирается, почтовое восстановление не подключено.
- Зависимости прежнего Capacitor CLI имеют три умеренных предупреждения аудита (xcode/uuid). Высокое предупреждение source-map-js исправлено обновлением. Мобильные сборки не переделывались.
- Большой Blockly chunk остаётся в лениво загружаемом исходном курсе. B2B не загружает его при входе.
- Перед реальным пилотом настроить HTTPS, резервное копирование, доступ к серверу, хранение и удаление данных учеников. Коммерческая готовность не заявляется.
- Неиспользуемая первоначальная копия `D:/projects/kodik-b2b` осталась на диске: автоматическая проверка отклонила её удаление. Все изменения внесены в `D:/projects/kodik`; копия не участвует в запуске.
