Генератор демонстрационной школы проверен в отдельной базе: 3 пользователя, 3 задания, 3 назначения, 0 выдуманных попыток.

- `npm run test:b2b`: HTTP-интеграция с реальной SQLite, две школы, запрет доступа и подмены связей, скрытые тесты, проверка программ, перезапуск базы, ручная оценка, копирование, восстановление и отзыв сессий.
- `npm run test:smoke`: старые учебные, Blockly, runtime, облачные и Android-проверки; AI-тест обновлён под безусловное отключение провайдера.
- `npm run test:b2b:ui`: полный браузерный путь через регистрацию школы, выдачу аккаунтов, вход преподавателя, конструктор, назначение, выполнение учеником, обновление страницы и просмотр результата преподавателем.

## Ограничения первого пилота

- Python исполняется существующим учебным интерпретатором, не CPython. Нет импортов, классов и сторонних библиотек. Отдельный процесс имеет дедлайн, ограничение heap, вывода, операций и параллелизма. Для полного Python нужен отдельный контейнерный сервис; небезопасный запуск системного Python не добавлялся.
- Blockly не редактируется новым конструктором; сохранён исходный курс. Его локальный прогресс не смешивается с B2B.
- SQLite, лимиты и сервер рассчитаны на один экземпляр. Для большого SaaS нужны PostgreSQL, очередь исполнений и нагрузочные испытания.
- Восстановление учеников выполняет преподаватель; администратор использует recovery-код. Email не собирается, почтовое восстановление не подключено.
- Зависимости прежнего Capacitor CLI имеют три умеренных предупреждения аудита (xcode/uuid). Высокое предупреждение source-map-js исправлено обновлением. Мобильные сборки не переделывались.
- Большой Blockly chunk остаётся в лениво загружаемом исходном курсе. B2B не загружает его при входе.
- Перед реальным пилотом настроить HTTPS, резервное копирование, доступ к серверу, хранение и удаление данных учеников. Коммерческая готовность не заявляется.
