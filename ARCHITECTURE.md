# Архитектура B2B

React/TypeScript/Vite сохраняются. Node.js 24.19+ обслуживает API и production-сборку. SQLite (`node:sqlite`, WAL, foreign keys) хранится в `data/kodik.sqlite`, путь задаётся KODIK_DB. База и секреты исключены из Git.

Организация → пользователи (admin/teacher/student), курсы → модули → уроки → задания. Группы связаны с учениками, назначения — с группами и заданиями. Попытки содержат снимок задания, результат и код. Черновики хранятся сервером. Все запросы ограничены organization_id; связи проверяются на сервере. Ученику доступны только опубликованные задания его групп. Тесты и ожидаемые ответы ему не передаются.

Сессии: случайные 256-битные токены, в базе SHA-256, HttpOnly/SameSite=Strict cookie, 7 дней. Пароли — scrypt с солью. Мутации проверяют Origin. Есть лимиты входа и проверки кода. Администратор выдаёт учётные данные и сбрасывает пароли с отзывом сессий. Восстановление администратора — одноразовый recovery-код; в базе только хеш.

Проверка принимает исходный код, не доверяя результату клиента. Отдельный процесс учебного интерпретатора запускается без секретов окружения, с permission model, 48 МБ heap, дедлайном и ограниченным выводом. Язык не имеет файловых или сетевых примитивов. Есть лимит одновременных процессов. Скрытые тесты остаются на сервере. Статусы: passed, failed, runtime_error, pending_review, checker_error. Ручная проверка доступна преподавателям своей школы.

SQLite — для одного сервера. При росте: PostgreSQL, общее хранилище лимитов/сессий, очередь и выделенные контейнеры CPython. Не использовать SQLite через сетевой диск между репликами.

Справочные первоисточники: [SQLite API Node.js](https://nodejs.org/download/release/v24.19.0/docs/api/sqlite.html), [ограничения permission model](https://nodejs.org/download/release/v24.19.0/docs/api/permissions.html). Permission model не заменяет языковую изоляцию: недоверенный JavaScript в runner не принимается.
