# UX-аудит Kodik B2B и бренд-кита — 19 октября 2026

Этап A редизайна. Аудит выполнен на текущей сборке B2B (`npm start`, отдельная база с демонстрационной школой из `scripts/seed-b2b.mjs`), окно 1440 × 900, роли преподавателя и ученика. Исходный код не менялся.

## 1. Что есть сейчас

| Область | Реализация | Оценка |
|---|---|---|
| Стек | React 19 + Vite, один SPA с hash-маршрутами (`src/b2b/App.tsx`, 1761 строка), стили одним файлом `src/b2b/styles.css` (2297 строк) | Рабочий, но вся оболочка и почти все экраны — в одном компоненте |
| Сервер | Node 24, SQLite, роли admin/teacher/student, изоляция по `organization_id`, ученические DTO без скрытых тестов | Надёжная основа. Права проверяются на сервере — UI менять безопасно |
| Конструктор | 6 шагов (`Builder.tsx`): информация → содержимое → редактор → проверка → предпросмотр → публикация; 7 шаблонов; автосохранение и конфликты; проверка эталона и «неправильных» решений перед публикацией | Сильнейшая часть продукта по логике, слабая по подаче |
| Составные уроки | `LessonEditor.tsx`: шаги text / code / practice / question / final / summary, версии, программа для группы | Работает, но спрятан за кнопкой «Сценарий урока» |
| Среда ученика | `Workspace.tsx`: вкладки «Задание / Теория / Подсказки / Попытки», редактор, «Запустить», «Проверить решение», консоль, ввод для пробного запуска | Хорошая основа трёхчастной раскладки |
| Blockly | Только исходный курс по `?legacy=1` | Создавать Blockly-задания в B2B нельзя |

### Реальные возможности учебного движка (ограничивают конструктор)

- **Python, написание кода** — да. Способы проверки: «ожидаемый вывод», «входные данные и тест-кейсы» (до 12 тестов, флаг «скрытый»), «ручная проверка» с критериями.
- **Python со стартовым кодом/шаблоном** — да: поле «стартовый код» и 7 серверных шаблонов.
- **Учебные правила** — да: обязательные приёмы (if, for, while, def, return, input, вложенный цикл…), их проверяет структурный checker.
- **Проверка качества** — да: эталон должен пройти все тесты, неправильные примеры должны быть отклонены. Без подтверждения публикация закрыта.
- **Теория** — да, как шаги составного урока (текст, пример кода, вопрос с вариантами, итог). Изображений и загрузки файлов нет.
- **Blockly и Blockly → Python** — **нет** в B2B. После ревью решено не показывать их в конструкторе вовсе: только строка в справке (ENGINE_CAPABILITIES.md).
- Интерпретатор — учебный, не CPython: нет `import`, классов и сторонних библиотек. Это нужно объяснять в редакторе ученика и в конструкторе.
- **Подписка, места, тарифы** — в модели данных нет. Экран подписки можно спроектировать, но подключать нечего.

## 2. Проблемы интерфейса

Приоритет: **P1** мешает основному сценарию или доступности, **P2** заметно замедляет работу, **P3** — визуальная согласованность.

### Кабинет преподавателя

| # | Пр. | Проблема | Где |
|---|---|---|---|
| T1 | P1 | Главная не отвечает на вопросы «что ждёт проверки» и «кто требует внимания». Половину первого экрана занимает декоративный баннер «Обучение начинается с хорошей идеи» с иллюстрацией `{ learn }` | `#overview` |
| T2 | P2 | Четыре плитки-счётчика (курсы, ученики, успешные решения, на проверке) показывают числа без действия. Клик по «На проверке» никуда не ведёт | `#overview` |
| T3 | P2 | В меню шесть пунктов: «Участники» — отдельный раздел, хотя по ТЗ ученики относятся к группам, а преподаватели — к школе. Плюс карточка «Лаборатория Kodik» в сайдбаре отвлекает от работы | сайдбар |
| T4 | P2 | Курсы — крупные карточки с декоративной шапкой `{ }`. При 10+ курсах нет поиска, фильтра по статусу и плотного списка | `#courses` |
| T5 | P2 | Группа — одна длинная карточка: ученики, программы и назначения идут подряд, есть три кнопки на всю ширину. С несколькими группами придётся долго прокручивать | `#groups` |
| T6 | P2 | Задания — плоский список без курса, урока, статуса проверки качества и фильтров. Действия «Копия / Снять» стоят без подтверждения рядом | `#tasks` |
| T7 | P3 | Ошибка склонения «1 модулей · 3 заданий» | карточка курса |
| T8 | P3 | Верхняя строка «Обновлено в 12:43 · Обновить · Учимся создавать · дата» — четыре служебных элемента без главного действия | шапка |

## 4. Что оставить из бренда

1. Wordmark Kodik и знак K. — оригинальные векторы, три версии.
2. Зелёная гамма: CTA `#17463A`, Primary Green `#235E51`, Ink `#17352E`, тёплые off-white поверхности.
3. Nunito — основной шрифт (уже лежит в `public/fonts/Nunito.ttf`, переменный 200–1000).
4. Terracotta как единственный тёплый акцент: метка «Задание», внимание, ученические мотивационные элементы.
5. Визуальный язык «маленький блок → следующий шаг»: нумерованные шаги, мягкие карточки, путь Блок → Блок+код → Python.
6. Запреты: без градиентов, неона, стекла, 3D.

## 5. Предлагаемые изменения и причины

| Изменение | Причина |
|---|---|
| Добавить функциональные цвета: success `#24694C`, warning `#9A5B12`, danger `#B3412F`, info `#1F6F8B` с мягкими фонами | В ките есть только мягкие фоны успеха/ошибки. Для таблиц результатов и статусов тестов нужен текстовый цвет с контрастом ≥ 4,5:1. Все четыре ≥ 5,3:1 на Surface и ≥ 4,8:1 на своих мягких фонах |
| Ввести `--line-strong #7F8B84` (3,51:1 на Surface, 3,30:1 на Canvas) для границ полей и чекбоксов | Line кита 1,26:1 не различима как граница поля (WCAG 1.4.11) |
| Третьего, более светлого уровня текста не вводить | Проверенный `#6B7A73` даёт 4,47:1 — уже ниже AA. Всё вспомогательное — Muted `#5F6E67` |
| Фокус: двойное кольцо 2 px `#FFFEFA` + 2 px `#1F6F8B` | Синяя информационная обводка видна на зелёных кнопках и на светлом фоне; зелёная терялась бы на CTA |
| Радиусы: 8 (поля, кнопки), 12 (карточки, таблицы), 16 (модальные окна, ученические карточки), 20 (крупные ученические промо-карточки) | Радиусы кита 18–25 px рассчитаны на мобильные карточки. В плотных таблицах и формах они съедают место |
| Десктопная типографическая шкала 12–32 px (см. DESIGN_SYSTEM.md) | Шкала кита — презентация (28–88) и мобильный (13–32) |
| JetBrains Mono для кода | Кит допускает «отдельный технический monospace». JetBrains Mono — читаемые `0/O`, `l/1`, лигатуры можно отключить |
| Две плотности: преподаватель — компактная (строка таблицы 44 px, поля 40 px), ученик — свободная (поля 44 px, карточки с отступом 24 px) | Дополнение к ТЗ: две визуальные среды одного бренда |
| Убрать декоративные иллюстрации `{ learn }`, `{ }` с рабочих экранов | Принцип «никаких декоративных элементов, мешающих работе» |

Ничего из этого не внедрено в стили продукта: по дополнению к ТЗ замена стилей начинается после утверждения направления.

## 6. Что можно переиспользовать

- Сервер, API, модель прав и DTO — без изменений.
- Хуки `useMaterialDraft`, `useStudentDraft`, `useSubmission` — логика черновиков, конфликтов и очереди проверок не зависит от вида.
- `MinimalCodeEditor` — нумерация строк, отступы, размер шрифта. Его нужно оформить по токенам и выключить мобильную клавиатуру на десктопе.
- `Workspace` как общий экран ученика и предпросмотра (уже один компонент — это правильно).
- `Badge`, `Empty`, `Header`, `Glyph` — заменить на компоненты дизайн-системы с тем же API, чтобы не трогать логику экранов.
- Шаблоны заданий и учебные правила (`learningRules.json`) — источник для карточек выбора в конструкторе.
