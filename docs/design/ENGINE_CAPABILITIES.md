# Возможности учебного движка Kodik B2B — что может показывать интерфейс

Проверено 19 октября 2026 по коду (`src/pythonRuntime.ts`, `src/pythonExecution.ts`, `server/b2b/*.mjs`) и запуском. Конструкции Python прогнаны через тот же парсер и исполнитель, что и серверный runner. `npm run test:pilot` на рабочей сборке: 45 тестов и 70 сравнений с CPython 3.11.9 прошли.

**Правило для UI:** показываем как доступное только то, что есть в таблицах «Работает». Всё остальное либо не показываем, либо объясняем одной строкой без кнопки действия.

## 1. Python: учебный интерпретатор, не CPython

Собственный интерпретатор Kodik. Запускается в отдельном процессе на сервере: 48 МБ памяти, дедлайн, ограниченный вывод, до 10 000 шагов выполнения, до 250 строк и 12 000 символов. Файлов, сети и импортов нет. Интерфейс не должен называть его «Python 3» или имитировать CPython: подпись в редакторе — «Python · учебный интерпретатор».

### Работает (проверено запуском)

| Конструкция | Пример |
|---|---|
| print, input, int, str, len, range (в т. ч. с шагом) | `n = int(input())` |
| Числа (целые, дробные, `7 / 2 = 3.5`), строки, True/False/None, списки, индекс `a[0]`, присваивание по индексу | `a[0] = 5` |
| `+ - * / // % **`, строка × число | `'ab' * 3` |
| Сравнения, в том числе цепочкой | `1 < x < 5` |
| and, or, not | |
| if / elif / else, for по range и списку, while | |
| def с параметрами, return, вызов своих функций | |
| pass, комментарии `#`, несколько input подряд | |
| Сообщение о бесконечном цикле | «Программа выполняется слишком долго…» |

### Не работает (ошибка при запуске)

| Конструкция | Что видит ученик |
|---|---|
| `+=`, `-=`, `*=` | «Незнакомый фрагмент «= 5»» |
| break, continue | «Неожиданный знак «break»» |
| `print(…, end='')`, `sep=` | «Незнакомый фрагмент» |
| f-строки | «Ожидается «,»» |
| Методы: `.append()`, `.split()`, `.upper()` | «Незнакомый фрагмент «.append(1)»» |
| Срезы `s[1:3]`, оператор `in` | «Незнакомый фрагмент» / «Лишний фрагмент «in»» |
| float, max, min, abs, round, sum, list | «Сначала опиши функцию «max» через def» — **вводит в заблуждение** |
| Словари, кортежи, распаковка `a, b = 1, 2` | «Незнакомый фрагмент» |
| import, class, try/except | ошибка синтаксиса |
| Отступ не кратный 4 пробелам | «Используй отступ в 4 пробела» |

**Риск для пилота (P1).** Учитель, привыкший к школьному Python, напишет эталон с `+=`, `break` или `print(..., end='')`. Проверка качества поймает это сразу: эталон не пройдёт. Но учитель должен понять причину. Поэтому:
- в конструкторе — ссылка «Что умеет учебный Python» со списком выше;
- ошибка эталона показывается с пояснением и подсказкой замены (`s = s + 1`);
- сообщение «Сначала опиши функцию «max» через def» нужно заменить на «Функция max пока не поддерживается учебным Python» (правка текста в `pythonExecution.ts`, решение PD-12).

## 2. Типы заданий

| Тип | B2B-конструктор | Где в UI |
|---|---|---|
| Python: написать код с нуля | **Работает** | Быстрое создание |
| Python со стартовым кодом | **Работает** (поле `starter`) | Расширенные → «Стартовый код» |
| Python по шаблону (7 серверных шаблонов: вывод, ввод и вычисление, условие, цикл, функция, исправление ошибки, творческая) | **Работает** | Кнопка «Начать с шаблона» в списке заданий |
| Ручная (творческая) работа | **Работает** (`check_mode: manual` + критерии) | Расширенные → «Способ проверки» |
| Теория, пример кода, вопрос с вариантами (до 6), итог | **Работает**, но как шаг составного урока, не как задание | Сценарий урока |
| Изображения в материалах | Нет (нет загрузки файлов) | Не показывать кнопку |
| Blockly | **Нет в B2B** | Не показывать в конструкторе |
| Blockly → Python | **Нет в B2B** | Не показывать в конструкторе |

## 3. Автоматическая проверка

| Способ | Работает | Детали |
|---|---|---|
| Ожидаемый вывод (`output`) | Да | Сравнение вывода без входных данных |
| Тест-кейсы (`tests`) | Да | 1–12 тестов, ввод построчно, флаг «скрытый». Вывод нормализуется (пробелы в конце строк) |
| Ручная проверка (`manual`) | Да | Статус «На проверке» → преподаватель «Принять» / «Вернуть» с комментарием |
| Обязательные конструкции (`learning_rules`) | Да | 8 правил: переменная, input, if, for, while, def, return, вложенный цикл. Проверяется по выполнению, комментарии не считаются |
| Проверка качества перед публикацией | Да, **обязательна** | Эталон проходит все тесты + **хотя бы один** неправильный пример отклоняется (до 6). Без подтверждения публикация закрыта сервером |
| Произвольный Python-скрипт проверки | Нет | И не нужен для MVP |
| Сравнение чисел с допуском, регулярные выражения | Нет | Возможное расширение |

Статусы попытки: `passed`, `failed`, `runtime_error`, `pending_review`, `checker_error`. У скрытого теста ученик получает только «пройден / не пройден»; ввод, ожидаемый и фактический вывод не передаются. Это проверено серверным тестом.

## 4. Blockly — где существует

Только в исходном B2C-курсе (`?legacy=1`). Его прогресс хранится локально и не попадает в B2B-результаты. Технический прототип интеграции в B2B (блоки → учебный Python → существующая проверка) — `docs/adaptive/`, в продукт не подключён.

| Режим исходного курса | Значение |
|---|---|
| `blocks` | Собрать программу из блоков |
| `recognition` | Узнать, что делает код |
| `completion` | Дополнить код |
| `tokens` | Собрать код из готовых частей |
| `text` | Написать Python самостоятельно |

Уровни поддержки: `blocks → blocks_with_code → guided_code → code_tokens → free_code`. Именно эту лестницу показывает бренд-кит («Блоки → Блоки + Python → Код с подсказкой → Сборка кода → Свой Python»).

**Вывод для UI:** в B2B не показываем ни Blockly-типы заданий, ни лестницу этапов у ученика. В первой версии прототипа они были помечены «Скоро» — убраны из основного пути. Одна строка в справке конструктора: «Blockly-задания пока доступны только в исходном курсе Kodik».

## 5. Чего нет в серверной модели

| Функция | Статус | Что делает UI |
|---|---|---|
| Тарифы, лимит мест, срок доступа | Нет | Вкладка «Подписка» — только концепт в прототипе, в MVP не показывается |
| Расписание занятий | Нет | Не показываем «сегодня в 15:00»; показываем «урок 3 открыт» |
| Права преподавателя по группам | Нет: все преподаватели школы видят все группы | Подпись в «Школе»; решение PD-09 |
| Архив ученика | Нет; есть «Отключить доступ» (`active=0`, сессии завершаются, данные сохраняются) | Действие называется «Отключить доступ», не «Архивировать» |
| Пакетное создание учеников | Нет отдельного API; есть создание по одному | Пакетный диалог работает циклом по существующему API (PD-10) |
| Комментарий к автоматической попытке | Нет: комментарий только в ручной оценке | Не показываем поле в панели авто-попытки (PD-07) |
| Ручное переопределение автоматического результата | Запрещено сервером | Нет кнопки «Засчитать вручную» |
| Учёт открытых подсказок | Нет: все подсказки приходят клиенту сразу, поэтапность — только в интерфейсе | Не пишем ученику «учитель видит подсказки» |
| Показ правильного решения ученику | Никогда: эталон и `preview_solution` вырезаются из ученических ответов | Подсказки без готового решения |
| Загрузка изображений | Нет | Кнопки нет |
