# Пользовательские сценарии: как сейчас и как предлагается

«Сейчас» — рабочая сборка B2B на 19 октября 2026. Шаги взяты из e2e-сценария `tests/b2b.e2e.ts`: он проходит в Edge и кликает по реальному интерфейсу. Плюс ручной проход на демонстрационной школе (`scripts/seed-b2b.mjs`). «Предлагается» — прототип `prototype/index.html`. Число действий: клики по кнопкам и ссылкам без ввода текста. Ввод полей считается отдельно.

## 1. Преподаватель: группа → урок → задание → назначение → результаты

### Сейчас

| # | Экран | Действия | Кликов | Полей |
|---|---|---|---|---|
| 1 | Курсы | «Создать курс» → диалог → «Сохранить» | 3 | 2 |
| 2 | Курс | «+ Модуль» → «Сохранить»; «+ Урок» → «Сохранить» | 4 | 2 |
| 3 | Конструктор, шаги 1–4 | «+ Задание», затем 4 раза «Продолжить» | 5 | 6 |
| 4 | Шаг 5 «Предпросмотр» | Ввести правильный код → «Проверить пример решения» | 1 | 1 |
| 5 | Назад к шагу 4 | «К конструктору задания» → эталон → «Добавить неправильный пример» → «Проверить эталон…» | 3 | 2 |
| 6 | Шаг 6 | Перейти на шаг → «Сохранить и опубликовать» | 2 | 0 |
| 7 | Учебные группы | Пункт меню → «Создать группу» → «Сохранить» → «Добавить ученика» → «Сохранить» | 5 | 2 |
| 8 | Группа | «Назначить задание» → выбрать → «Выдать группе» | 2 | 1 |
| 9 | Результаты | Пункт меню → «Открыть решение» | 2 | 0 |
| | **Итого** | | **27** | **16** |

Где ломается:
- **Повторный ввод.** Правильная программа вводится дважды: как пример решения в предпросмотре (`preview_solution`) и как эталон (`reference_solution`).
- **Возврат назад.** Проверка качества стоит на шаге 4, а пробное решение — на шаге 5. Учитель идёт вперёд, затем возвращается.
- **Потеря контекста после публикации.** Конструктор не знает, для какой группы делается задание. После публикации нужно самому найти группу и назначить.
- **Пустой селект.** Если урок ещё не создан, конструктор показывает пустой «Место в программе». Создать урок оттуда нельзя.
- **Нет пути от группы.** Учитель думает «что дать 7А завтра», а интерфейс начинает с каталога курсов.
- Ученики добавляются по одному (5 полей на каждого) — см. сценарий администратора.

### Предлагается

| # | Экран | Действия | Кликов | Полей |
|---|---|---|---|---|
| 1 | Группы → «Python · Старт 7А» → вкладка «Программа» | 3 перехода | 3 | 0 |
| 2 | Урок 3 → «+ Задание» (урок и группа подставлены) | 1 | 1 | 0 |
| 3 | Раздел 1 «Задание» | | 0 | 2 |
| 4 | Раздел 2 «Решение и тесты» | Эталон, ввод двух тестов → «Заполнить вывод запуском эталона» | 1 | 3 |
| 5 | Раздел 3 «Типичная ошибка» | «Скопировать эталон и изменить» → правка | 1 | 1 |
| 6 | Раздел 4 «Проверка качества» | «Проверить задание» | 1 | 0 |
| 7 | Раздел 5 «Публикация» | 7А уже отмечена → «Опубликовать и выдать» | 1 | 0 |
| 8 | Группа → «Результаты» | Вкладка → ячейка матрицы | 2 | 0 |
| | **Итого** | | **10** | **6** |

Курс и урок создаются один раз на программу, а не на каждое задание. Если урока нет, «+ Задание» доступно и из списка заданий: урок выбирается в «Расширенных настройках» или создаётся там же.

Безопасность не ослаблена:
- проверка качества по-прежнему обязательна, кнопки публикации заблокированы до неё с объяснением рядом;
- любое изменение после проверки сбрасывает подтверждение. Сервер делает это и сам (`task-quality.mjs`);
- выданная версия не меняется при правках, и это написано рядом с кнопкой.

## 2. Ученик: вход → задание → проверка → следующее

### Сейчас

| # | Действие | Кликов |
|---|---|---|
| 1 | Вход | 1 |
| 2 | Главная → «К моим курсам» (ведёт в список курсов, не в задание) | 1 |
| 3 | Карточка курса → «Продолжить обучение» | 1 |
| 4 | Прочитать условие (вкладка «Задание»), написать код | 0 |
| 5 | «Запустить» → «Проверить решение» | 2 |
| 6 | После успеха — кнопка следующего задания (есть в `Workspace`) | 1 |
| | **Итого** | **6** |

Где ломается:
- лишний переход через список курсов;
- в редакторе остаётся сайдбар преподавательского вида (−240 px);
- на десктопе видна мобильная клавиатура;
- подсказки — список без поэтапности.

Черновик сохраняется на сервер, есть защита `beforeunload` и разрешение конфликтов двух вкладок (`useStudentDraft`) — здесь потерь нет.

### Предлагается

Вход → «Продолжить обучение» (сразу в задание) → «Запустить» → «Проверить решение» → «Следующее задание». Итого **5** кликов. Контекст сохраняется: «← К курсу» возвращает в путь курса на текущий урок.

## 3. Администратор: организация → преподаватели → ученики → группы → подписка

### Сейчас

| # | Действие | Кликов | Полей |
|---|---|---|---|
| 1 | Регистрация школы → сохранить код восстановления | 2 | 4 |
| 2 | «Участники» → «Добавить участника» → роль → «Сохранить» — на каждого человека | 2 × N | 4 × N |
| 3 | Группы — как у преподавателя (у администратора те же права) | 3 | 1 |
| 4 | Подписка | — | — |

Для класса из 25 учеников это 50 кликов и 100 полей. Пароли придумывает администратор (от 10 символов), их надо где-то записать и раздать. Информации о подписке нет: в модели данных её нет.

### Предлагается

| # | Действие | Кликов | Полей |
|---|---|---|---|
| 1 | Школа → «Преподаватели» → «Добавить преподавателя» | 3 | 3 |
| 2 | Группа → «Добавить учеников» → вставить список имён → «Создать N аккаунтов» → карточки входа для печати | 3 | 1 (список) |
| 3 | Школа → «Ученики»: поиск, сброс пароля, «Отключить доступ» | по необходимости | |
| 4 | «Подписка» — **не показывается в MVP**; концепт в прототипе с пометкой | — | — |

Пакетное создание реализуемо без серверных изменений: последовательные `POST /api/users` и `POST /api/groups/:id/members` с паролями, сгенерированными в браузере, и итоговым экраном «создано / ошибка» по каждой строке. Атомарность и ключ повтора — серверное улучшение (PD-10).

## 4. Где возможна потеря несохранённых изменений

| Место | Сейчас | Решение |
|---|---|---|
| Конструктор задания | Автосохранение, локальная копия, конфликты двух авторов, `beforeunload` | Оставить; сделать индикатор сохранения заметным (ошибка — красная плашка с «Повторить») |
| Сценарий урока | То же (`useMaterialDraft`) | Оставить |
| Редактор ученика | Серверный черновик, две вкладки, `beforeunload` | Оставить |
| Модальные формы (курс, группа, участник) | Состояние формы живёт в диалоге; закрытие по «Отмена» сбрасывает ввод — нужно проверить на сборке | Подтверждение закрытия, если в форме есть ввод |
| Комментарий в ручной оценке | Поле в диалоге попытки | Черновик комментария в `sessionStorage` до отправки |
