# Исследование UX конкурентов

**Источники и ограничения.** Обзор составлен по публичным страницам продуктов, документации для преподавателей и демонстрационным материалам: CodeHS Teacher Help, Codio Docs, Stepik Teach, документация CodeRunner, JetBrains Academy for educators. Учительских аккаунтов не создавали. Перед финальным дизайном выводы стоит выборочно проверить на живых аккаунтах: CodeHS и Stepik бесплатны для преподавателя.

Интерфейсы не копируются: берём только проверенные подходы.

## CodeHS — кабинет преподавателя и классы

| Сильные решения | Сложности | Для Kodik |
|---|---|---|
| Раздел «Sections» (классы) — центр работы. Внутри класса: ученики, назначенные курсы, прогресс по урокам | Очень много пунктов меню. Новичок теряется между Courses, Sections, Assignments, Gradebook и Tools | Группа — главная рабочая сущность: «Группы → группа → вкладки Ученики / Программа / Результаты» |
| Gradebook-матрица «ученик × задание» с цветом статуса и переходом к коду | Матрица на сотни колонок без группировки по модулям | Матрица результатов с группировкой по модулям и фильтром «требуют внимания» |
| Просмотр решения ученика: код, история попыток, автотесты | Ручная оценка спрятана глубоко | Единая панель «Решение»: код, тесты, история, «Принять / Вернуть с комментарием» |
| Массовое создание учеников по списку и код класса | — | Массовое создание аккаунтов списком с выдачей карточек входа (сервер это уже умеет поштучно) |

## Codio — редактор и предпросмотр преподавателя

| Сильные решения | Сложности | Для Kodik |
|---|---|---|
| Учебный текст слева, IDE справа, консоль внизу — устойчивая раскладка | Полноценная IDE с деревом файлов и терминалом перегружает школьника | Та же трёхчастная раскладка, но без дерева файлов: одна программа `main.py` |
| Автор видит задание «глазами ученика» и может пройти его | Переключение между режимами автора и ученика — отдельные экраны | Предпросмотр — **живая панель** в конструкторе, не отдельная страница |
| Тесты описываются как «ввод → ожидаемый вывод» в форме, без кода | Продвинутые проверки требуют скриптов | Для Kodik достаточно формы. Скрипты-проверки не вводим |

## Stepik — конструктор курсов

| Сильные решения | Сложности | Для Kodik |
|---|---|---|
| Иерархия Курс → Модуль → Урок → Шаг. Шаги — горизонтальная лента с иконкой типа | Мелкие иконки шагов трудно различать; в ленте 20+ шагов теряется навигация | Дерево курса слева, «лента шагов» урока с подписями типа |
| Добавление шага: выбор типа из галереи карточек с описанием | Галерея из 20+ типов. Многие шаги учителю не нужны | Галерея из 5 типов, неподдерживаемые помечены «Скоро» |
| Редактор шага — WYSIWYG + настройки проверки рядом | Настройки проверки кода требуют Python-шаблона проверяющего | Проверку описываем таблицей тест-кейсов, код проверяющего не нужен |

## CodeCombat — мотивация ученика

| Сильные решения | Сложности | Для Kodik |
|---|---|---|
| Мгновенная визуальная обратная связь на каждый запуск | Игровая графика отвлекает подростков и не подходит для «профессионального» Python | Мгновенная обратная связь — да, игровая графика — нет |
| Подсказки появляются по нарастающей; ошибка объясняется словами героя | Персонаж говорит неточными формулировками | Поэтапные подсказки: «Направление → Пример → Почти решение», с понятной причиной ошибки и исходным текстом ошибки Python под катом |
| Видимый путь уровней | Рейтинги и соревнования включены по умолчанию | Путь курса — да. Рейтинги и соревнования — нет (ТЗ, несовершеннолетние) |

## Moodle + CodeRunner — автопроверка

| Сильные решения | Сложности | Для Kodik |
|---|---|---|
| Таблица тестов «Test / Expected / Got» с зелёными и красными строками — ученик сразу видит, что не так | Форма вопроса с десятками полей; шаблоны проверки на Twig/Python | Таблица результатов тестов «Ввод / Ожидалось / Получено» |
| Флаги «Hide rest if fail», «Display: show / hide» у теста | Названия флагов непонятны без документации | Один переключатель «Виден ученику» с подсказкой, что будет видно |
| Обязательный «Answer» (эталон), который проверяется при сохранении | Ошибка проверки эталона показывается сырым трейсбэком | У Kodik уже есть проверка эталона и неправильных решений — показываем её человеческим чек-листом |

## JetBrains Academy — инструкции и IDE

| Сильные решения | Сложности | Для Kodik |
|---|---|---|
| Описание задания и код в одном окне IDE; панель «Check» всегда видна | Профессиональная IDE перегружает начинающих | Кнопки «Запустить» и «Проверить» закреплены над консолью и не прокручиваются |
| Постепенное раскрытие инструментов IDE по мере курса | Переход между режимами ученика и автора требует плагина | Прогрессивное раскрытие: на первых уроках в редакторе только код и запуск; ввод, история и размер шрифта — в меню «Ещё» |
| Подсветка строки ошибки и переход к ней из сообщения | — | Клик по ошибке в консоли переводит курсор на строку |

## Выводы для Kodik

1. **Группа — центр работы преподавателя** (CodeHS): из неё выдают программу, смотрят прогресс, добавляют учеников.
2. **Конструктор = форма слева + живой предпросмотр справа** (Codio, Stepik). Шаги — разделы одной среды, не отдельные страницы.
3. **Тесты — таблица, не код** (Codio, CodeRunner). Кнопка «Проверить тесты» прогоняет эталон сразу.
4. **Трёхчастная среда ученика** (Codio, JetBrains): условие, редактор и консоль с закреплёнными действиями.
5. **Мотивация без соревнования** (вопреки CodeCombat): путь, освоенные навыки, следующий шаг — без рейтингов.
6. **Матрица результатов с фильтром «требуют внимания»** (CodeHS Gradebook) вместо витрины метрик.
