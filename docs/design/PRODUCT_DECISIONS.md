# Продуктовые решения: версии, результаты, роли, конструктор

У каждого пункта:
- **как сейчас** — проверено по коду сервера и тестам `test:pilot`, 19 октября 2026;
- **предложение**;
- **что нужно на сервере**.

Статус «Открыт» — нужен ответ владельца Kodik.

## Конструктор

### PD-01. Быстрое создание и расширенные настройки на одном экране — *предложено*
**Сейчас:** мастер из 6 шагов. Проверка качества на шаге 4, пробное решение на шаге 5, правильная программа вводится дважды.
**Предложение:** один экран из пяти обязательных разделов: задание, решение и тесты, типичная ошибка, проверка качества, публикация. Плюс свёрнутые «Расширенные настройки» со значениями по умолчанию (PD-03). Рейка слева — оглавление со статусом разделов, а не мастер: можно заполнять в любом порядке. Ожидаемый вывод тестов заполняется кнопкой «Заполнить вывод запуском эталона» — она использует существующий `POST /api/preview/run`.
**Сервер:** изменений не требуется. `preview_solution` заполняется из эталона на клиенте.
**Вывод по п. 2 ТЗ:** да, оба уровня реализуются в одном интерфейсе через прогрессивное раскрытие. Отдельный «режим эксперта» не нужен.

### PD-02. Обязательная проверка качества остаётся — *решено сервером*
**Сейчас:** публикация невозможна без подтверждения точной ревизии. Эталон проходит все тесты, хотя бы один неправильный пример отклоняется.
**Предложение:** не ослаблять. Снизить трудоёмкость:
- кнопка «Скопировать эталон и изменить» для типичной ошибки;
- объяснение слабых тестов человеческим языком с предложением конкретного теста.

**Сервер (после пилота):** автоматические «мутанты» эталона (заменить `*` на `+`, `<` на `<=`) как дополнительные неправильные примеры.

### PD-03. Значения по умолчанию быстрого режима — *открыт*
Предложение:
- способ проверки — тест-кейсы;
- первый тест виден ученику как пример, остальные скрыты;
- сложность — начальная;
- стартовый код — `# Напиши решение здесь`;
- обязательных конструкций нет;
- подсказок нет;
- урок и группа — из контекста, откуда открыт конструктор.

Вопрос владельцу: скрывать ли по умолчанию все тесты, кроме первого, или показывать все?

## Версии и результаты

### PD-04. Изменение опубликованного задания — *решено сервером, нужен UI*
**Сейчас:** правка увеличивает ревизию черновика. Выданные группам версии не меняются (`task_versions` неизменяемы, назначение хранит `version_id`). Повторная публикация создаёт новую версию для **новых** назначений. Тест: «published draft edits do not alter an assigned version».
**Предложение:** в конструкторе опубликованного задания — плашка «Опубликована версия 2. Группе 7А выдана версия 1» и кнопка «Выдать версию 2 повторно». В результатах у попытки — «версия N».
**Сервер:** нет. Нужен только запрос «какие версии выданы каким группам» — данные уже есть в `assignments`.

### PD-05. Старые попытки — *решено сервером*
**Сейчас:** каждая попытка хранит снимок задания (`attempts.snapshot`), заголовок и ревизию. Проверка идёт по снимку, а не по текущему заданию.
**Предложение:** показывать «версия N» в истории и панели решения. Не пересчитывать старые попытки при правке задания.

### PD-06. Повторное прохождение — *решено сервером, нужен UI*
**Сейчас:** «Назначить повторно» (`repeat_of`) создаёт новый контекст. Успех и черновик из прошлого назначения не переносятся. Тест: «repeat assignment pins new publication without borrowing success or drafts».
**Предложение:**
- в матрице — последнее назначение, рядом значок «повтор 2»;
- в панели ученика — вкладки «Текущее / Прошлые прохождения»;
- ученик видит повтор как отдельное задание с пометкой «Повтор».

### PD-07. Комментарий к автоматической попытке — *открыт*
**Сейчас:** комментарий есть только при ручной оценке. Автоматический результат переоценить нельзя (`400`).
**Предложение:** оставить запрет на смену автоматического статуса. Добавить комментарий преподавателя к любой попытке, без изменения статуса.
**Сервер:** `POST /api/attempts/:id/comment` + поле в DTO ученика. Желательно для пилота: учителю важно ответить «посмотри на строку 2».

### PD-08. Перевод ученика в другую группу — *открыт, нужен сервер*
**Сейчас:** удаление из группы — `DELETE group_members`, без истории. Ученик сразу теряет доступ к заданиям старой группы. Попытки остаются в базе и в его личной истории, но из матрицы старой группы он исчезает: матрица строится по текущим участникам. В новой группе назначения новые, прошлые успехи не засчитываются. Тест: «another group creates another context; archiving preserves history».
**Предложение:**
- действие «Перевести в группу…» с подтверждением, где перечислены последствия;
- в матрице старой группы — фильтр «Выбывшие» с их результатами;
- по умолчанию прошлые успехи **не** переносятся, чтобы не смешивать разные версии заданий.

**Сервер:** таблица членства с `joined_at / left_at` вместо удаления строки. Желательно до пилота, если на пилоте возможны переводы.

### PD-09. Права преподавателя по группам — *открыт*
**Сейчас:** все преподаватели школы видят и меняют все группы, задания и результаты своей школы. Изоляция между школами есть и проверена.
**Предложение для пилота:** допустимо, если в школе один-два преподавателя. Написать об этом в разделе «Школа».
**После пилота:** владелец группы и совместное преподавание (`group_teachers`), проверка на сервере.

### PD-10. Пакетное создание учеников — *предложено*
**Сейчас:** по одному, пароль придумывает человек.
**Предложение:** вставить список имён → логины по шаблону группы, пароли генерируются → карточки входа для печати, показываются один раз.
**Сервер:** для пилота не обязательно (цикл по существующему API). Для продаж — атомарный `POST /api/groups/:id/students:batch` с ключом повтора.

### PD-11. Подписка и места — *концепт, вне MVP*
**Сейчас:** нет ни тарифов, ни лимитов, ни сроков.
**Предложение для будущей модели:** место — активный ученический аккаунт. Отключение доступа освобождает место, решения сохраняются. При исчерпании мест не блокировать вход существующих учеников, а запрещать создание новых.
**В MVP:** вкладка не показывается.

### PD-12. Ограничения интерпретатора — *открыт, влияет на пилот*
**Сейчас:** нет `+=`, `break`, `print(end=)`, f-строк, методов, срезов, `in`, `float/max/min` (см. ENGINE_CAPABILITIES.md). Сообщение для `max(…)` — «Сначала опиши функцию «max» через def» — вводит в заблуждение.
**Предложение:**
1. До пилота:
   - исправить текст сообщения о неподдерживаемых встроенных функциях;
   - добавить справку «Что умеет учебный Python» в конструктор и в редактор ученика;
   - стартовые уроки писать в поддерживаемом подмножестве.
2. Отдельным решением — расширить интерпретатор. Порядок по пользе для школьной программы: `+=`, `in`, `break`, `print(end=)`, `float`, `max/min`, методы списков и строк.

**Сервер:** изменение учебного движка — только отдельной задачей с прогоном 70 эталонных сравнений с CPython.

### PD-13. Когда ученик видит правильное решение — *открыт*
**Сейчас:** никогда. Эталон и `preview_solution` вырезаются из ответов ученику (`safeTask`), это проверено тестом.
**Предложение для пилота:** не показывать. Подсказки строятся лестницей без готового кода.
**Возможное развитие:** «показать разбор» после срока или после принятого решения — флаг в задании + проверка на сервере.

### PD-14. Скрытые тесты — *решено сервером*
Ученик получает по скрытому тесту только «пройден / не пройден». Ввод, ожидаемый и фактический вывод не передаются (тест «hidden test input, expected output and runtime details never leak»). Преподаватель видит всё.

### PD-15. Доступ к результатам: преподаватель и администратор — *решено*
**Сейчас:** одинаковый доступ ко всем результатам школы. Только администратор:
- отключает и включает доступ;
- сбрасывает пароли преподавателям;
- добавляет преподавателей.

Ученик видит только свои попытки без кода других и без снимка задания.
**Предложение:** оставить. Пункт «Школа» в меню — только администратору.

### PD-16. «Архивирование» учеников — *открыт*
**Сейчас:** архива нет. Есть «Отключить доступ»: `active=0`, сессии отзываются, все данные и членство сохраняются (тест «blocking revokes sessions and preserves records»).
**Предложение для пилота:** называть действие честно — «Отключить доступ» — и фильтровать списки «Активные / Отключённые».
**После пилота:** архив выпускника — скрыт из групп, данные доступны в отчётах, место освобождается (PD-11).

### PD-17. Снятие задания с публикации — *решено сервером, UI исправлен*
**Сейчас:** снятие публикации запрещает **новые** назначения. Уже выданные версии продолжают работать (тест «unpublishing leaves lessons available»). Закрыть задание для группы — «Снять назначение» (`archived=1`): ученик теряет доступ, попытки и черновики сохраняются.
**Решение:** тексты подтверждений в прототипе исправлены. Первая версия неверно обещала, что ученики «больше не смогут отправлять решения».

### PD-18. Учёт подсказок — *открыт*
**Сейчас:** все подсказки приходят клиенту сразу. Поэтапность — только в интерфейсе, сервер не знает, сколько подсказок открыто.
**Предложение для пилота:** не обещать ученику и учителю учёт. Если учёт нужен, это серверное событие `hint_opened` и показ в панели решения.

### PD-19. Минимальная ширина окна — *предложено*
**Сейчас:** `body { min-width: 1280px }`. На ноутбуке 1366 × 768 с масштабом Windows 125% (1093 CSS px) появляется горизонтальная прокрутка всего приложения.
**Предложение:** полная поддержка от 1024 CSS px. Ниже 1200 сайдбар сворачивается в рейку иконок, ниже 1366 предпросмотр конструктора открывается кнопкой. В прототипе проверено: 0 px переполнения на 1093.
