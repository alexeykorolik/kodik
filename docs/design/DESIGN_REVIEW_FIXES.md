# Ревью дизайна: проблемы и исправления

Ревью прототипа `prototype/index.html` (версия 2), 19 октября 2026. Метод:
- автоматический проход в Edge через Playwright: скриншоты, клавиатура, переполнение на 5 размерах, ошибки консоли;
- сверка каждого экрана с серверной моделью (ENGINE_CAPABILITIES.md, PRODUCT_DECISIONS.md).

Скриншоты 1440 × 900 — в [screenshots/](screenshots).

Прототип — это материал для согласования, а не продукт. Данные в нём — пример, логика проверки имитирована.

**Приоритеты:** P1 — вводит в заблуждение или блокирует основной сценарий; P2 — замедляет или путает; P3 — согласованность.
**Статус:** «Исправлено» — в прототипе; «В плане» — при реализации (UI_IMPLEMENTATION_PLAN.md); «Решение» — ждёт ответа (PRODUCT_DECISIONS.md).

## Соответствие возможностям продукта

| # | Пр. | Проблема | Причина | Решение | Статус |
|---|---|---|---|---|---|
| R1 | P1 | Конструктор предлагал типы Blockly и Blockly → Python с меткой «Скоро» | Blockly есть только в исходном курсе, в B2B нет ни авторинга, ни проверки | Убраны из конструктора. Одна строка в справке «Blockly-задания пока доступны только в исходном курсе» | Исправлено |
| R2 | P1 | Подтверждение «Снять с публикации» обещало, что ученики не смогут отправлять решения | Сервер блокирует только новые назначения, выданные версии работают | Текст переписан по фактическому поведению, указан путь «Снять назначение в группе» | Исправлено |
| R3 | P1 | В панели решения была кнопка «Засчитать вручную» и комментарий для автоматической попытки | Сервер запрещает ручную оценку автоматических попыток; комментарий есть только у ручной | Две версии панели: автоматическая (только чтение, «Назначить повторно») и ручная («Принять / Вернуть» с комментарием) | Исправлено; PD-07 |
| R4 | P1 | Экран «Школа» показывал тариф, места и срок как работающие | В модели данных подписки нет | Вкладка «Подписка» помечена «концепт», с жёлтым предупреждением и пунктирной рамкой. В MVP не показывается | Исправлено; PD-11 |
| R5 | P1 | Ученику обещали «учитель видит, сколько подсказок ты открыл» | Учёта подсказок на сервере нет | Текст убран | Исправлено; PD-18 |
| R6 | P1 | У ученика была лестница «Блоки → … → Свой Python» | В B2B этапов Blockly нет | Заменено реальным прогрессом: выполнено заданий, текущая тема | Исправлено |
| R7 | P1 | Ограничения интерпретатора не видны учителю до первой ошибки | Нет `+=`, `break`, `end=`, методов, `in` и др. | Справка «Что умеет учебный Python» в конструкторе. Ошибка эталона показывает конструкцию и замену | Исправлено в прототипе; PD-12 |
| R8 | P2 | На обзоре было «2 занятия сегодня», у групп — «Сегодня 15:00» | Расписания в модели нет | Заменено реальными данными: «урок 3 открыт», число решений на проверке | Исправлено |
| R9 | P2 | Диалог приглашения показывал «свободно 33 места из 120» | Лимитов мест нет | Убрано | Исправлено |
| R10 | P2 | В матрице «На проверке» было у автоматических заданий | `pending_review` бывает только у ручных | Статус «?» только у ручного задания | Исправлено |
| R11 | P2 | Действие «Архивировать ученика» подразумевалось в IA | Архива нет, есть отключение доступа | Действие называется «Отключить доступ», с подтверждением и последствиями | Исправлено; PD-16 |

## Конструктор заданий

| # | Пр. | Проблема | Решение | Статус |
|---|---|---|---|---|
| B1 | P1 | Мастер из 7 шагов: тип, основное, содержимое, редактор, проверка, предпросмотр, публикация. Для простого упражнения слишком длинно | Один экран: 5 обязательных разделов + свёрнутые «Расширенные настройки» с показанными значениями по умолчанию | Исправлено; PD-01 |
| B2 | P1 | Правильная программа вводится дважды (пример в предпросмотре и эталон) | Один эталон; предпросмотр использует его | Исправлено; PD-01 |
| B3 | P1 | Публикация и назначение — разные места, контекст группы теряется | «Опубликовать и выдать» с группой из контекста и сроком в одном разделе | Исправлено |
| B4 | P2 | Ожидаемый вывод вписывается руками, легко ошибиться | «Заполнить вывод запуском эталона» (через существующий `preview/run`) | Исправлено |
| B5 | P2 | Обязательный неправильный пример непонятен | Раздел «Типичная ошибка ученика» с пояснением и кнопкой «Скопировать эталон и изменить» | Исправлено |
| B6 | P2 | После правки неясно, действительна ли проверка | Любая правка тестов, эталона или ошибки сбрасывает статус: «Задание изменено после проверки — проверьте снова» | Исправлено |
| B7 | P2 | Рейка была мастером: нельзя увидеть сразу, что не заполнено | Рейка — оглавление со статусами: ✓, !, номер. Для расширенных настроек — текущее значение | Исправлено |
| B8 | P2 | Тест без ожидаемого вывода не подсвечивался | Красная рамка, текст «Нет ожидаемого вывода», `aria-invalid`, статус «!» в рейке | Исправлено |
| B9 | P3 | На 1280 px форма тестов была узкой | Сайдбар в конструкторе — рейка 64 px; предпросмотр ниже 1366 px открывается кнопкой | Исправлено |
| B10 | P2 | Теория и вопросы смешивались с заданием | Ссылка «сценарий урока»: теория и вопросы — шаги урока, как в модели данных | Исправлено |

## Доступность и разрешения

Результаты автоматического прохода (`review-log.json` рядом со скриншотами):

| Проверка | Результат |
|---|---|
| 25 первых Tab на обзоре | Порядок логичный (навигация → состояния → действия → списки), у всех видимое кольцо фокуса |
| Модальное окно | Фокус переходит внутрь, удерживается при Tab, Esc возвращает фокус на кнопку открытия |
| Редактор кода | Tab вставляет отступ; Esc, затем Tab — выход из редактора |
| Разделители панелей | Стрелки меняют ширину (420 → 444 px), есть `role="separator"` и подпись |
| Рейка конструктора | Enter переносит фокус в поле раздела |
| Переполнение по горизонтали | 0 px на всех 7 экранах: 1280 × 800, 1366 × 768, 1440 × 900, 1920 × 1080 |
| 1366 × 768 при масштабе Windows 125% (1093 CSS px) | Было: прокрутка в конструкторе (111 px) и среде ученика. После правок — 0 px |
| Масштаб браузера 200% на 1440 (720 CSS px) | **Не проходит** WCAG 1.4.10: оболочка требует 1024 px, появляется горизонтальная прокрутка. Предложение — PD-19 и раздел «Масштаб» в DESIGN_SYSTEM.md |
| Ошибки консоли | 0. Найденная ошибка JS в конструкторе исправлена |
| Контраст | Все текстовые пары токенов ≥ 4,5:1, границы полей 3,5:1 (расчёт по формуле WCAG) |

Не проверялось: экранный диктор (NVDA/JAWS), axe-core, Windows High Contrast. Это входит в план реализации.

| # | Пр. | Проблема | Решение | Статус |
|---|---|---|---|---|
| A1 | P1 | `body { min-width: 1280px }` в продукте: прокрутка на ноутбуках с масштабом 125% | Минимум 1024 CSS px, адаптация сайдбара и конструктора | Исправлено в прототипе; PD-19 |
| A2 | P2 | 200% масштаб требует горизонтальной прокрутки | Поддержать чтение условия и результатов в одну колонку от 640 CSS px; редактор и матрица — допустимое исключение 2D-содержимого | В плане |
| A3 | P3 | Матрица результатов передавала статус только цветом | Знак ✓ ✗ ? + `aria-label` «имя, задание: статус» | Исправлено |
