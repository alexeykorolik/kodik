# Отчёт о UX-проверке

**Статус: тестирование с преподавателем не проводилось.** Ниже — что проверено на прототипе и протокол сессии, которую нужно провести после утверждения направления (п. 16 ТЗ).

## 1. Что проверено (19 октября 2026)

Прототип `prototype/index.html` открыт во встроенном браузере Chromium.

| Проверка | Результат |
|---|---|
| 1440 × 900: все 7 экранов | Без наложений и обрезанного текста |
| 1280 × 800: конструктор | Сначала форма тестов была слишком узкой (сайдбар 240 + рейка 220 + предпросмотр 480). Исправлено: в конструкторе сайдбар сворачивается в рейку иконок 64 px, ниже 1366 px предпросмотр по умолчанию скрыт и открывается кнопкой |
| 1280 × 800, 1366 × 768: среда ученика, обзор | Горизонтальной прокрутки страницы нет (`scrollWidth` < ширины окна) |
| 1920 × 1080: среда ученика | Редактор занимает освободившееся место, панели не растягиваются бесконечно |
| Сценарий конструктора | Проверка → «Ошибка 2 проходит все тесты» → «Добавить тест 21 → 42» → повторная проверка → публикация открыта → диалог назначения группе |
| Сценарий ученика | «Проверить решение» с ошибкой `n + 2` → «Пройдено 1 из 3», diff по открытому тесту, скрытый тест без данных; подсказки открываются по очереди |
| Контраст | Все текстовые пары токенов ≥ 4,5:1, границы полей 3,5:1 (скрипт расчёта по формуле WCAG) |
| Найденные и исправленные ошибки прототипа | Подсветка активного экрана, непоследовательные результаты тестов в панели решения, нечитаемая иконка «⋯», полупрозрачная нижняя панель конструктора |

Не проверено: экранный диктор (NVDA), axe-core, реальная работа с сервером — прототип статичный.

## 2. Протокол сессии с преподавателем информатики

**Участник:** преподаватель информатики, знает Python, не видел Kodik B2B. Для пилота в Беларуси он уже есть (`PROGRESS.md`).
**Формат:** 45 минут, очно или по видеосвязи с демонстрацией экрана, ноутбук 1366 × 768 или 1920 × 1080, запись экрана с согласия.
**Стенд:** рабочая сборка B2B после этапа 2 плана, пустая школа + группа из 3 тестовых учеников.

### Перед стартом (5 мин)
Одна минута рассказа: «Kodik — платформа для уроков Python. Думайте вслух. Мы проверяем интерфейс, а не вас».

### Задания

| # | Задание участнику | Успех | Замер |
|---|---|---|---|
| 1 | Войдите и создайте курс «Python 7 класс» | Курс в списке | Время, ошибки |
| 2 | Добавьте модуль и урок «Ввод и вычисления» | Урок в структуре | Время |
| 3 | Создайте задание: ученик вводит число, программа выводит удвоенное | Задание сохранено | **Время от «Создать задание» до сохранения; цель — 3–5 мин** |
| 4 | Убедитесь, что задание нельзя решить неправильно (без подсказки о кнопке) | Нажата проверка задания, добавлен недостающий тест | Нашёл ли проверку сам |
| 5 | Посмотрите задание глазами ученика и отправьте неправильное решение | Увидел обратную связь | Понял ли, что видит ученик |
| 6 | Опубликуйте и назначьте группе со сроком в пятницу | Назначение создано | Время, колебания |
| 7 | Где вы увидите, кто из учеников не справился? | Открыта матрица или «Требуют внимания» | Путь |

### Что наблюдаем
- Где участник останавливается дольше 10 с.
- Какие поля и слова вызывают вопрос («эталон», «скрытый тест», «учебные правила», «ревизия»).
- Какие возможности участник ищет и не находит.
- Ошибки: неверный клик, возврат назад, потеря введённого.

### После заданий (5 мин)
1. Что было самым непонятным?
2. Чего не хватило, чтобы использовать это на завтрашнем уроке?
3. Оценка сложности создания задания от 1 до 7 (SEQ).
