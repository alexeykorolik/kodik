# Аудит Kodik: реализация P0/P1/P2

Дата:1октября2026. База ce50ab3. Объём подтверждён пользователем: все программные изменения. Не менялись общий мобильный стиль, число заданий, язык курса.

## Реализовано

- Адаптация всех78новых задач: guided_code, code_tokens, free_code; сохранение реального формата, содержательная короткая практика и возврат в тот же урок. App больше не обходит материализацию extended-форматов.
- Индивидуальные primarySkill/practices/requires. Prerequisites и вся глава автоматически не получают credit.
- AST checker с зависимостями вывода/рисунка вместо поиска regex. Мёртвые, неиспользуемые и перезаписанные вычисления не дают evidence. Скрытые входы/данные/аргументы функций; настоящая вложенная повторяемость, включая вызов функции внутри цикла.
- AI получает ограниченный summary продвинутого AST без исходного кода, значений и имён; сервер восстанавливает доверенный формат/материал и validator допускает знакомые while/input/return.
- Подготовленные corrective/review: списки, ввод, рисование, базовые навыки в code-first; отдельные отрицательные ID без наград основного курса.
- Бесплатный разбор темы23–100; подсказки по решению продолжают учитываться.
- Прогресс: навыки первыми, история «Что повторить» и оценки во вкладках. Старые ошибки/имя/звёзды сохранены.
- Подсветка Python, панель Tab/( )/:/кавычки с сохранением фокуса/выделения. Доступность кнопки Python44px, нативное поле Blockly не теряется при resize.
- Центральные события Supabase, анонимные IDs, идемпотентность, очередь офлайн, длительность завершения. Строгий список категорий: неизвестные поля и значения отбрасываются. Нет кода, имени, email, текста ответа/ошибки.
- Постоянные квотыAI в Supabase, подписанный HttpOnly cookie, IP/global ceilings, failclosed при сбое базы и обычный fallback в приложении. Локальный счётчик переживает reload.
- Удалены старые Course100 UI/data/solutions/runtime/test и оставшиеся CSS-селекторы. README описывает один источник истины.
- Протокол10новичков, реальныхтелефонов и последующего пилота50–100, пустая таблица результатов и SQL агрегатов. Настоящие результаты не выдуманы.

Сборка и весь smoke suite прошли:78эталонов,78×3формата, все короткие практики, альтернативные кавычки/имена, обходыchecker, безопасные лимиты, mastery/resume/миграция, AIprivacy/fallback, schema/cookie/quota/origin/events201.

ПолныйUI suite:91пройдены,2AIсценария были выключены флагом,1тест потребовал обновления под реально адаптируемый формат. После исправления теста все100заданий успешно пройдены подряд (40.6с); дваAI UI сценария отдельно включены и оба прошли. Итого все94сценария подтверждены, включая новичка, touchBlockly, размеры360–1920, viewport420, сохранение/карту/историю/аккаунт и новое восстановление списков. Скриншоты: docs/mobile-ux/audit-*.png.

Миграция003 выполнена в настоящей Supabase из Vercel. Проверены20конкурентных claims к одному bucket:8разрешены,12отклонены. Для anon запрещены SELECT learning_events и EXECUTE limiter RPC. Проверено чтение REST сервисным ключом (HTTP200). Служебный provisioning принимает только фиксированную миграцию, требует случайный серверный токен и в последней версии истекает через15мин; из финального deployment удаляется, временные deployments удаляются после верификации.

## Ограничения

Реальных10участников и физическихiPhone/Android ещё нет. Визуальные проверки — браузерная эмуляция. Checker обеспечивает учебные ограничения; это не доказательство эквивалентности любой Python-программы. Старую отсутствующую историю ошибок не восстановить. Аналитика не равна авторизации и не синхронизирует аккаунт; удаление данных браузера создаёт новый anonymous learner. Время завершения включает паузы после первого открытия. При длительном офлайне очередь ограничена5000событиями. Groq имеет собственные квоты; безлимитность не обещается.
