# Подготовка сервера для платного пилота

Сервер ещё не выбран. Ниже — что проверено локально и что обязательно повторить на выбранной машине до подключения школы. Публичное размещение выполняется только по отдельному решению владельца.

## Архитектурные ограничения

- Один экземпляр приложения на одну SQLite-базу (WAL). Второй процесс с той же базой запускать нельзя: очередь проверок и лимиты входа живут в одном процессе.
- Node.js 24 (используются `node:sqlite` и модель разрешений `--permission` для исполнителя).
- Приложение слушает HTTP на `127.0.0.1`; HTTPS обеспечивает обратный прокси на той же машине.

## Обязательные переменные окружения

| Переменная | Значение |
|---|---|
| `NODE_ENV` | `production` |
| `KODIK_ORIGIN` | точный HTTPS-адрес, например `https://kodik.example.ru` (без пути) |
| `KODIK_DB` | абсолютный путь к базе на постоянном томе |
| `KODIK_TRUSTED_PROXIES` | IP-адрес прокси, через который приходят запросы (обычно `127.0.0.1`), или `none` |
| `PORT`, `HOST` | по умолчанию `4173` и `127.0.0.1` |

Без `KODIK_TRUSTED_PROXIES` production-запуск остановится с объяснением. Причина: за прокси все соединения приходят с адреса прокси, и без этой настройки все школы делили бы один сетевой лимит входа (300 попыток за 15 минут) — ошибки входа одной школы блокировали бы остальные. Заголовок `X-Forwarded-For` учитывается только для соединений от указанного прокси и только его правая (добавленная прокси) часть, поэтому ученик не может обойти лимит, подставив свой заголовок. Проверка: `tests/proxy-limits.mjs`.

Пример nginx (фрагмент):

```nginx
location / {
    proxy_pass http://127.0.0.1:4173;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;
    client_max_body_size 1m;
}
```

Одна школа за общим NAT использует один сетевой бюджет: 300 попыток входа за 15 минут на адрес и 15 на логин. Для класса из 30 учеников этого достаточно; если в школе одновременно входят несколько классов, это нужно проверить на занятии.

## Обновление уже работающей школы

1. Резервная копия: `node scripts/database-backup.mjs $KODIK_DB /backups/kodik-YYYYMMDD-HHMM.sqlite`.
2. Проверка восстановления копии: `node scripts/verify-backup.mjs BACKUP.sqlite /tmp/restore-probe.sqlite`.
3. Остановить службу (активные проверки дорабатывают до 45 с, очередь сохраняется в базе).
4. Развернуть новую версию, `npm ci`, `npm run build`.
5. Запустить службу: миграции применяются при старте; база новее приложения не открывается.
6. Сразу выполнить `npm run reverify:published -- --db $KODIK_DB`. Пока среда проверки не подтверждена для выданных версий, новые проверки выданных заданий не выставляют оценок: ученик видит «Проверка этого задания временно недоступна…», черновики сохраняются, принятые проверки ждут и автоматически продолжаются после подтверждения. Если отчёт содержит `failed`, эти задания не продолжаются — их нужно разобрать вручную; старые результаты и снимки не меняются.
7. Проверить `/api/health` и вход администратора.

### Репетиция на заполненных данных (выполнена локально)

- `scripts/fill-pilot-database.mjs` заполняет новую базу через API выбранного релиза: владелец, карточка клиента, подключённая школа, лицензия, преподаватель, класс, блоковый и Python-черновики, принятые, неудачные и ручные работы с оценкой преподавателя, запрос помощи, рекомендация.
- `scripts/rehearse-upgrade.mjs FILLED NEW` восстанавливает копию текущим кодом, проверяет неизменность всех прежних строк (включая очередь проверок) и рабочие сценарии по HTTP.

Результат 2026-10-19: база предыдущего релиза (коммит `cbbb6dd`, схема 14) → схема 15; 42 таблицы, 66 прежних строк без изменений; вход всех ролей, черновики, журнал (4 работы), ручная оценка и её история, рекомендация, запрос помощи, лицензия и карточка клиента на месте; новая проверка до подтверждения среды — `runtime_unconfirmed`, после `reverify-published` (2 версии подтверждены) — «Выполнено» с записанной средой; старые попытки не изменены. Копия рабочей базы `data/kodik.sqlite` (схема 10, 1 организация) также перенесена в схему 15 без потерь; сам файл не изменялся.
