# Учебные правила школьных заданий — 19 октября 2026

Первый шаг интеграции механик исходного курса: B2B-проверка использует существующие `runPythonAst` и `structureError`. Неиспользуемый код, комментарии и недостижимые ветви не подтверждают применение приёма: учитываются зависимости наблюдаемого результата.

## Работа преподавателя и ученика

В конструкторе на шаге «Проверка» появился список «Что нужно применить в решении»: переменная, if, for, while, функция, return, input, вложенные циклы. Это публичные требования; ученик видит тот же список в условии. Без выбора сохраняется прежняя проверка вывода. Для ручной работы приёмы описываются в критериях, автоматический список очищается.

Шаблоны условия, цикла и функции теперь включают соответствующие правила. Среди неправильных примеров функции есть вычисление квадрата без def: оно даёт верный вывод, но не достигает учебной цели и отклоняется. Эталон должен пройти одновременно тесты и учебные правила. Проверка не требует дословного совпадения с эталоном, конкретных имён переменных или форматирования.

Общий WorkspaceView показывает публичные требования и конкретную подсказку. Обычный «Запустить» исполняет код без оценки; «Проверить» проверяет и результат, и выбранные приёмы. Предпросмотр следует тем же правилам, сохраняя авторский код отдельно и не создавая ученических попыток.

## Данные и исполнение

Миграция 10 добавляет tasks.learning_rules с пустым списком для старых заданий. Включены сохранение, история авторских ревизий, копирование задания и курса, предпросмотр, доказательство качества, неизменяемые версии и долговечная очередь. Уже выданная версия продолжает требовать свои приёмы после редактирования авторского черновика и перезапуска.

Правила валидируются по фиксированному списку: неизвестные значения и повторы отклоняются. В изолированный дочерний процесс передаются только код, ввод и разрешённые правила. Сохраняются ограничения памяти, времени, языка, вывода и Node permissions. AST, наблюдаемые зависимости и скрытые данные ученику не возвращаются. Ошибка структуры на скрытом тесте сообщает только общий отрицательный результат.

Непустые правила включены в fingerprint подтверждения. Для пустого списка сохранён старый формат fingerprint, чтобы историческое воспроизведение прежних ревизий оставалось возможно. После изменения исполнителя прежний опубликованный снимок сохраняет своё доказательство. Перед новой выдачей нужно сохранить новую ревизию, подтвердить её проверку и опубликовать. Повторная проверка прежней ревизии не подменяет доказательство неизменяемого снимка; публикация объясняет необходимое действие. Старые выданные версии продолжают работать.

До изменения создана data/backups/pre-learning-rules.sqlite, схема 9. Восстановление в verified-restore-learning-rules.sqlite сохранило все 3 исходные записи в 28 таблицах, применило схему 10 и подтвердило HTTP readiness. Миграции 1–10 больше не редактировать.
