## 4. Как принимается решение

`resolveAdaptiveSupport` — единственное место расчёта ступени. `learningFlow` применяет решение и фиксирует evidence. App открывает результат, не сравнивает mastery с собственным порогом. Незавершённая сессия возобновляется в сохранённом формате, чтобы refresh не сменил редактор под черновиком.

Проверяется объединение teaches/practices и все целевые навыки, а не самый сильный. Первые знакомства защищены от ускорения. При среднем освоении сохраняется исходный курс. После настоящего адаптивного решения формат может переноситься на релевантную практику. Без проверенного варианта сохраняется исходное упражнение.

Selector выбирает основное/corrective/review задание из конечного пула, проверяя prerequisites элемента и исходного урока. Review не может вводить ещё не изученный цикл. Повторения имеют отдельные отрицательные ID и не входят в завершения курса.

## 5. Пороги и обоснование

Уверенность: mastery ≥ **0.72**, ≥ **2 самостоятельных успеха**, отсутствие текущей серии ошибок. Между сменами формата нужны **2 новых самостоятельных успеха** по каждому целевому навыку. Ниже 0.40 — слабое освоение, 0.40–0.72 — развивающееся; сами диапазоны не вызывают скачок.

Восстановление: **2 разных содержательных ошибки** в текущей сессии и серия ошибок релевантного навыка. Review: mastery ≥ 0.35 и настоящий перерыв ≥ **3 дней**. После нового перерыва повторение снова доступно: историческая completion-запись не запрещает его навсегда.

0.72 и базовые веса оставлены из проекта; два свежих подтверждения — минимальная устойчивость. Это продуктовые эвристики, не исследовательски установленные параметры. Самостоятельные блоки дают evidence; пошаговое знакомство, подсказка и готовое решение не считаются самостоятельным успехом. Базовая формула mastery сохранена с этим уточнением.

## 6. Upgrade, downgrade и восстановление

`blocks → blocks_with_code → guided_code → code_tokens → free_code`: максимум одна ступень за решение. Upgrade — при следующем открытии, не посреди ввода. Счётчики после смены фиксируются; прежний успех нельзя использовать повторно для следующего повышения.

После двух разных ошибок предлагается «Закрепить на примере». Если вариант доступен, добавляется одна ступень помощи. Практика возвращает **в то же незавершённое задание**. Blockly-черновик и попытки сохраняются; несовместимые tokens/выбор очищаются при смене формата. Text draft восстанавливается при refresh в том же формате. Повторение не закрывает основной урок и не начисляет ему звёзды. Новое восстановление снова требует свежих ошибок.

Пустая проверка сохраняет обычную попытку/обратную связь, но не снижает mastery и не создаёт corrective. Повтор ответа не даёт новое evidence; разобранный текст нормализуется, поэтому изменение одних пробелов не считается новой ошибкой. Существующие правила звёзд не отменены: corrective не добавляет отдельного штрафа.

## 7. UX

Сохранена иерархия «цель → рабочая область → результат». Каждый формат объясняет текущее действие, смена формата сопровождается человеческим сообщением без числового mastery. Справка соответствует вводу. В tokens видна полная программа, включая готовое тело цикла. После знакомства Python автоматически раскрывается; на desktop blocks-with-code показывает зеркало рядом, при сильной поддержке его можно открыть по желанию.

Карта различает текущий/завершённый/закрытый шаг; причина блокировки доступна вне отключённой кнопки. Practice сохраняет контекст основного урока в прогрессе главы. Выход через карту не отключает оценку выбранного обычного урока. Распознавание переменной исполняет полный подготовленный пример, а не чтение отсутствующей переменной.

## 15. Ограничения

Mastery — грубая модель evidence, не измерение долговременного понимания. Повтор знакомого ответа может переоценивать перенос навыка. Corrective переиспользует проверенные исходные задачи, не большой набор независимых примеров. DurationSeconds — ориентиры, не измеренные медианы. Классификация по сообщениям эвристическая; точность причин требует наблюдений. Не все исходные уроки имеют каждый вариант: остаётся fallback.

Не проверены физическая клавиатура телефона, Safari/VoiceOver, живая запись Supabase и перенос между устройствами. Fresh offline launch/service worker не добавлен. Нет подтверждения понятности для 10 новичков: автоматические проверки этого не доказывают.

## 17. Проверка на 10 людях и приоритеты

Первым: самостоятельный первый блок/значение, понимание связи с Python, заметность «Добавить блок», настоящая мобильная клавиатура. Затем: смысл пропуска/tokens/свободного кода, изменения помощи и возврата из corrective. Отдельно: не выглядит ли повтор наказанием, понятны ли звёзды и закрытая глава. Для каждого затруднения фиксировать действие, экран, паузу и дословную фразу, не общий отзыв «нравится».

Далее исправлять воспроизводимые блокеры → тексты/обратную связь → качество независимых повторений и темп адаптации. Только по наблюдениям пересматривать веса/пороги. Пока не расширять курс, не вводить AI и не начинать новый редизайн. Протокол — [USER_TESTING.md](USER_TESTING.md).
