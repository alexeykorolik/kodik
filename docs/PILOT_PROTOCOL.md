# Протокол пилота Kodik

## Статус

Программная подготовка выполнена. Результатов настоящих участников и физических телефонов пока нет. Автотесты и эмуляция не считаются user testing.

## 10 новичков: 25–35 минут каждый

Чистый профиль, собственный прогресс, согласие на запись экрана без персональных данных. Для несовершеннолетнего согласовать участие с ответственным взрослым. Записать анонимный номер P01–P10, модель/ОС/браузер, исходный опыт. Обучающие задания начать с первого; подготовленное прохождение для демо не использовать как результат участника.

1. Без устных подсказок пройти первый вывод и изменить сообщение. Записать время до первого действия, проверки, подсказки, остановки.
2. Показать Python своих блоков и своими словами объяснить команду и значение. Просьба «объясни» не должна содержать ответ.
3. Пройти первое заполнение/сборку частей. После перехода написать похожую строку с другим сообщением; измерить самостоятельность переноса, а не запоминание эталона.
4. Открыть разбор темы. Проверить, что ученик понимает разницу теории и подсказки по решению.
5. Открыть прогресс: понимает ли освоение навыков, темы повторения и доступ к истории?
6. После самостоятельной части отдельно показать code-first примеры23/50/58/67/79/92 на тестовом профиле. Эти демонстрации не считать освоенными заданиями новичка. Для понимающего основу участника наблюдать две разные ошибки и возврат из короткой практики в тот же урок.
7. Закрыть/открыть сайт, продолжить. Потерять сеть после загрузки и убедиться, что решение сохраняется.

Когда участник просит помощь, спросить «Что ты ожидал сделать?», отметить препятствие и время. Любая устная инструкция отмечается отдельно. Не заставлять искусственно ошибаться в основной самостоятельной части.

Основной показатель: доля самостоятельно прошедших первый переход и написавших похожую строку. Дополнительно: медианное время, подсказки/проверки, остановки, понятая связь блок→Python, восстановление после практики. Не писать «8/10», пока не получены10реальных результатов.

## Телефоны

Минимум один физический iPhone/Safari и один Android/Chrome. В таблицу занести модель, ОС, браузер и дату; размеры эмуляции писать отдельно.

- Адресная строка свёрнута/развёрнута: внешняя страница закреплена, CTA доступна.
- Blockly: добавить, соединить, изменить число/текст/переменную, длинный блок, масштаб, собственная клавиатура без Safari prompt.
- Python: длинная программа, каретка/выделение, горизонтальная/вертикальная прокрутка, Tab,( ),:,кавычки, системная клавиатура, закрытие/открытие, портрет/альбом.
- На открытой клавиатуре CTA и активная строка остаются доступны; ошибок фокуса и потери ответа нет.
- Теория/подсказка/ошибка/результат/рисунок/сворачивание редактора, VoiceOver/TalkBack базовая навигация.
- Карта без наложения заголовка;4раздела навигации;skills/история/оценки;после reload состояние сохранено.
- Потеря сети и восстановление: локальная работа и последующая отправка событий без дублей.

## Пилот50–100человек

Запускать после устранения блокирующих проблем10очных тестов. Проверить включённую аналитику, миграцию003 и серверные квоты. Наблюдать отправку событий, нулевую передачу исходного кода/имён, AI fallback, недоступность базы. Не собирать запись экрана в централизованные события. ПодсказкиAI допускают квоты; потребление контролируется глобальным дневным бюджетом.

Файл `docs/pilot-results.csv` — пустой шаблон, не результаты. SQL для агрегатов — `supabase/pilot_report.sql`. Анонимный идентификатор сбрасывается при удалении браузерных данных: число ID нельзя выдавать за число уникальных людей. Данные пилота можно удалить администратором по диапазону дат/анонимным ID; публичного endpoint чтения/удаления нет.
