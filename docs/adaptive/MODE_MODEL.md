# Модель режимов решения

Режим решения — способ, которым ученик собирает и отправляет программу одного задания.
- `blocks` — Блоки;
- `mixed` — Блоки + Python;
- `python` — Python.

Документ фиксирует однозначные правила **до** изменения схемы. Сервер проверяет их одновременно с появлением API режимов. Реализация — `src/adaptive/modePolicy.ts`: общий модуль клиента и сервера, таблица сочетаний покрыта тестом.

## 1. Четыре понятия

| Понятие | Где задаётся | Кто меняет | Значение |
|---|---|---|---|
| **Поддерживаемые режимы версии** `supported` | Опубликованная версия задания: `learning_config.modes` | Автор задания при публикации | Чем задание *можно* решать. Python входит всегда: это базовая возможность продукта и единственный режим старых заданий. Блоковые режимы появляются только с доказанным блоковым образцом (§6 ТЗ, PUBLICATION_PROOF) |
| **Разрешённые режимы назначения** `allowed` | Назначение группе: `mode_policy.allowed` | Преподаватель группы | Подмножество `supported`. Явное множество, не вычисляемое по умолчанию из задания |
| **Стартовый режим** `start` | `mode_policy.start` | Преподаватель группы | Обязан входить в `allowed`. С него ученик начинает, если ещё не работал над назначением |
| **Кто разрешает переход** `switching` | `mode_policy.switching` | Преподаватель группы | `free`, `teacher` или `locked` (§3) |

Индивидуальная настройка ученика (`override`) может задать свои `allowed`, `start` и `switching`. Её `allowed` — подмножество `supported` версии, а не обязательно назначения. Преподаватель вправе открыть ребёнку режим, не открытый группе, но не режим, которого нет у задания.

## 2. Как «Python всегда разрешён» сочетается с закреплением

Python всегда **поддерживается** версией: им можно проверить любое задание. Но **разрешён** он в назначении только если входит в `allowed`. Назначение «только блоки, закреплено» легально: Python в нём есть в `supported`, но отсутствует в `allowed`. Противоречия нет, потому что это разные понятия.

Старые Python-задания после миграции: `supported = ['python']`, у их назначений `allowed = ['python']`, `start = 'python'`, `switching = 'locked'`. Анализ эталона новые режимы им **не включает**.

## 3. Переключение

| `switching` | Что видит ученик | Как сменить режим |
|---|---|---|
| `free` | Переключатель со всеми режимами из `allowed` | Сам, в любой момент между запусками. Работа каждого представления сохраняется |
| `teacher` | Текущий режим. Остальные из `allowed` показаны как «откроет учитель» | Преподаватель делает **предложение** конкретного режима конкретному ученику. Ученик видит «Учитель предлагает перейти в Python» и сам нажимает «Перейти» или «Позже». Учитель может и сразу **перевести**, но переключение произойдёт при следующем открытии задания, а не посреди набора |
| `locked` | Только текущий режим | Только преподаватель меняет политику или делает override |

Текущий режим ученика — серверное состояние `assignment_mode_state.mode`. Оно меняется только явным действием:
- выбором ученика при `free`;
- принятием предложения;
- действием преподавателя.

Каждое изменение — событие в `mode_events` с автором, временем и причиной.

## 4. Таблица допустимых сочетаний (сервер)

Для каждого запроса `draft`, `run` и `submit` с режимом `m`:

| Условие | Ответ |
|---|---|
| `m ∉ supported(version)` | 409 `mode_not_supported` — «Это задание нельзя решать в этом режиме» |
| `m ∉ allowed_eff` | 409 `mode_not_allowed` — «Учитель не открыл этот режим». Для черновика — см. §5 |
| `switching_eff ≠ 'free'` и `m ≠ current` | 409 `mode_switch_required` — «Сначала перейдите в этот режим» |
| иначе | Разрешено |

Эффективная политика: `allowed_eff = override.allowed ?? policy.allowed`, `switching_eff = override.switching ?? policy.switching`, `start_eff = override.start ?? policy.start`. Если `current` ещё не задан или не входит в `allowed_eff`, текущим считается `start_eff`. Само состояние при этом не меняется молча.

Валидация политики при сохранении:
- `allowed ≠ ∅`;
- `allowed ⊆ supported`;
- `start ∈ allowed`;
- `switching ∈ {free, teacher, locked}`;
- при `locked` переключателя нет, текущий режим = `start`.

## 5. Работа ученика при изменении политики

| Событие | Поведение |
|---|---|
| Учитель меняет стартовый режим | Не влияет на тех, кто уже работает. Влияет на ещё не начавших |
| Учитель убрал режим, в котором ребёнок работает | Черновик этого режима **остаётся и читается**. Сохранение черновика в нём разрешено (это безопасная собственная работа). Запуск и отправка — 409 с объяснением и кнопкой перехода в доступный режим. Автоматического переключения нет |
| Потеря доступа к назначению или аккаунту | Сохранение черновика тоже запрещено — это обычная проверка доступа. Ранее сохранённое не удаляется и вернётся с доступом |
| Повторная отправка (тот же ключ) | Возвращает ту же операцию, даже если политика уже изменилась |
| Тот же ключ, другое содержимое | 409. Сравниваются назначение, режим и фактическое решение: код или сериализация блоков |
| Принятая в очередь проверка, политика изменилась | Проверяется по правилам и версии, **зафиксированным при приёме** (`submission_jobs.snapshot` + `policy`). Не переоценивается |
| Принятая в очередь проверка, доступ отозван | Задание очереди → `cancelled` с причиной «Доступ к заданию изменён». Это не попытка ученика и не неудача. Инфраструктурный сбой — отдельно, `checker_error` «повторите отправку» |

## 6. Черновики

| Черновик | Хранится | Общий между |
|---|---|---|
| Блоки | `assignment_block_drafts(user, assignment)` | `blocks` и `mixed`: это одно рабочее поле |
| Python | `assignment_drafts(user, assignment)` (существует) | Только `python` |

Код из блоков **не копируется** в Python-черновик автоматически. В будущем возможна явная кнопка «Скопировать мой код из блоков» с меткой в попытке (`copied_from_blocks`). Такая попытка не считается доказательством самостоятельного переноса. В первой версии кнопки нет.

## 7. Повторное назначение

Новое назначение имеет собственные `assignment_mode_state`, черновики и попытки. От прежнего прохождения ничего не наследуется, даже если задание то же.
