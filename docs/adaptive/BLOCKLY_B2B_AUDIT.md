19 октября 2026, этап 0. Обозначения статуса во всех документах `docs/adaptive/`:

| Статус | Значение |
|---|---|

## 1. Как Blockly устроен в B2C (`?legacy=1`) — Есть

| Часть | Файл | Что делает |
|---|---|---|
| Определения блоков | `src/blocks.ts` | Стандартные блоки Blockly 12 + свои `kodik_define`, `kodik_call` (функция без параметров) |
| Каталог | `src/blockCatalog.ts` | 11 типов с русскими подписями: `text_print`, `text`, `math_number`, `variables_set/get`, `math_arithmetic`, `logic_compare`, `controls_if`, `controls_repeat_ext`, `kodik_define`, `kodik_call` |
| Редактор | `src/BlocklyEditor.tsx` | Тема Kodik, renderer `zelos`, мобильная клавиатура, черновик в `localStorage`, добавление блока в «свободное место» |
| Внутреннее представление (IR) | `src/learningEngine.ts` | `workspaceToProgram()`: живое рабочее поле → `Program { statements: Stmt[] }` |
| Отображение Python | `learningEngine.renderPython()` | IR → текст Python **только для показа** |
| Исполнение | `learningEngine.runProgram()` | **Собственный JS-исполнитель IR**: лимит 1000 операций, без `input` |
| Проверка | `checkLesson()` | Сравнение вывода с `expectedOutput` + функция `validate(program)`, написанная вручную на каждый урок |
| Режимы уроков | `Lesson.mode` | `blocks`, `recognition`, `completion`, `tokens`, `text` |
| Уровни поддержки | `src/adaptiveSupport.ts` | `blocks → blocks_with_code → guided_code → code_tokens → free_code` |
| Прогресс | `src/progress.ts`, `mastery.ts` | Локально в браузере, на сервер B2B не попадает |

### Проверка: можно ли взять B2C-цепочку как есть — нет

Мы прогнали все 22 блоковых решения B2C через генератор B2C и учебный интерпретатор B2B. Запускаются **17 из 22**. Пять уроков с повтором и функциями падают на ошибке «неверное имя счётчика»: генератор пишет `for __kodik_repeat in range(3):`, а B2B-интерпретатор запрещает имена, начинающиеся с `__`.

Другие причины не брать цепочку B2C в B2B:

1. **Второй исполнитель.** B2C проверяет блоки собственным JS-движком (`runProgram`), а не учебным Python. Две реализации семантики неизбежно разойдутся. ТЗ запрещает дублировать проверку.
2. **Нет ввода.** В IR и каталоге нет `input`. Задачи вида «получить число и …» в блоках не собираются.
3. **Нет серверной проверки.** `workspaceToProgram` требует живой объект `Blockly.Workspace`, а `validate()` пишется кодом на каждый урок. Учитель B2B так не может.
4. **Пропуски и подстановки.** Пустое место превращается в `...` и `kind: 'missing'`, неизвестные блоки молча становятся `missing`. Для серверной проверки нужен явный отказ с причиной.

## 2. Что переиспользуем — PoC

| Что | Как |
|---|---|
| Пакет `blockly@12.3.1` и русская локаль | Без изменений |
| Определения `kodik_define` / `kodik_call` | Импорт `src/blocks.ts` без правок |
| Идея языконезависимого IR из `learningEngine.ts` | Переосмыслена: B2B-транслятор работает напрямую с JSON-сериализацией Blockly и выдаёт Python для **существующего** интерпретатора |
| Тема и подсветка «Python-зеркала» из B2C | Перенести в B2B-компонент при интеграции (этап 3) |
| Учебные правила (`learningRules.json`, `pythonStructure.ts`) | Применяются к сгенерированному Python тем же структурным checker. Проверено в PoC |

**Не переиспользуем:**
- `runProgram` / `checkLesson` — второй исполнитель;
- `renderPython` — несовместимые имена счётчиков;
- мобильную клавиатуру — B2B только для десктопа.

**B2C не меняется.** Все новые файлы лежат в `src/adaptive/`, существующие модули только импортируются.

## 3. Новое в PoC — PoC

| Файл | Назначение |
|---|---|
| `src/adaptive/blockProgram.ts` | Детерминированный транслятор `Blockly JSON → учебный Python`, версия `blocks-py/0.1`. Без зависимости от Blockly, поэтому работает и в браузере, и в доверенном процессе проверки. Белый список из 21 блока, лимиты, объяснимые ошибки, карта «блок → строки» |
| `src/adaptive/blocklyBlocks.ts` | Новые блоки `kodik_input_int` («ввести целое число» → `int(input())`) и `kodik_input_text` («ввести текст» → `input()`). Панель блоков строится только из палитры задания |
| `src/adaptive/referenceAnalysis.ts` | Анализ эталона: навыки, палитра, причины несовместимости |
| `src/adaptive/poc/` + `adaptive-poc.html` | Технический интерфейс: три режима, синхронный Python, проверка по тестам. Только `npm run dev` → `/adaptive-poc.html`, в production-сборку не входит |
| `tests/adaptive-blockly.poc.ts` | 108 проверок: блоки → серверная трансляция → **существующий** `grade()` из `server/b2b/grader.mjs` |

## 4. Ответы на вопросы этапа 0

| # | Вопрос | Ответ |
|---|---|---|
| 1 | Как Blockly устроен в B2C | См. §1: рабочее поле → IR → свой JS-исполнитель; Python только для показа |
| 2 | Какие блоки и генераторы есть | 11 блоков; генератор `renderPython` для показа. Официальный `blockly/python` не используется, и это правильно: он генерирует конструкции вне учебного подмножества |
| 3 | Как проверяются блоковые задания | Вывод + ручная функция `validate` на урок, в браузере |

| 5 | Как хранятся попытки и версии B2B | `task_versions.snapshot` — полный JSON задания; `attempts`: `code`, `snapshot`, `version_id`, `assignment_id`, `status`, `result`; черновики — `assignment_drafts(user, assignment, code, revision)`. См. ADAPTIVE_TASK_SCHEMA.md |
| 6 | Как расширить конструктор без поломки API | Одно новое JSON-поле задания `learning_config`. Оно автоматически попадает в снимок версии. Python-задания без него работают как раньше |
| 7 | Что действительно нужно на сервере | Режим и блоки в попытке и задании очереди, черновик блоков, трансляция внутри процесса-исполнителя, политика режимов в назначении. Подробно — ADAPTIVE_TASK_SCHEMA.md |
| 8 | Ограничения интерпретатора | Подтверждены заново (ENGINE_CAPABILITIES.md). Транслятор не генерирует ничего вне поддерживаемого: вместо `+=` блок «увеличить на» даёт `x = x + 1` |

## 5. Вывод этапа 0

Интеграция надёжна при трёх условиях:
1. **Один исполнитель.** Блоки → Python → существующий учебный интерпретатор и существующий `grade()`.
2. **Доверенная трансляция.** Сервер принимает структуру блоков, сам переводит её в Python и не доверяет тексту клиента.
3. **Белый список.** Блок существует, только если есть проверенное соответствие в учебном Python.

PoC подтверждает все три (ADAPTIVE_TEST_REPORT.md). Рекомендация — **продолжать** после согласования архитектуры и схемы.
