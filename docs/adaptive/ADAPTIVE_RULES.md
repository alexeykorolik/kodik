# Правила адаптации: первая версия

**Статус: План.** Ничего из этого не реализовано. Пороги — стартовые гипотезы для проверки с преподавателем, а не образовательные нормы. Машинного обучения и AI нет.

## 1. Принципы

1. **Kodik рекомендует — решает человек.** Ученик сам принимает предложение в пределах режимов, разрешённых учителем. Учитель может отключить рекомендации и задать режим вручную.
2. **Ничего не блокируется рекомендацией.** Ошибочная рекомендация не мешает продолжать в текущем режиме.
3. **Не переключать во время работы.** Предложение появляется после проверки решения или при открытии следующего задания, но не посреди набора.
4. **Навыки по отдельности.** Нет общего уровня ученика: переменные можно уже писать на Python, а условия ещё собирать блоками.
5. **Блоки ≠ Python.** Успех в блоках не подтверждает навык в Python.
6. **Без клик-метрик.** Время и число кликов не используются как доказательство знания.

## 2. Сигналы

Все сигналы берутся из уже хранимых или запланированных данных (ADAPTIVE_TASK_SCHEMA.md):

| Сигнал | Источник | Есть ли сейчас |
|---|---|---|
| Принятое задание, режим, версия, навыки версии | `attempts` + `task_versions.snapshot` | Режима нет (План: `attempts.mode`) |
| Неудачные попытки подряд | `attempts` | Есть |
| Ошибка выполнения и ошибка учебного правила | `attempts.status` / `result` | Есть |
| Открытые подсказки | Нет серверного учёта (PD-18) | **Нет.** Правила работают без этого сигнала, пока его нет |
| Повторное прохождение | `assignment_operations.payload.repeat_of` и `audit_log` (`assignment.repeated`); отдельного столбца нет | Есть, косвенно |

## 3. Стартовые правила (конфигурация, а не код)

```jsonc
{
  "version": 1,
  "order": ["blocks", "mixed", "assembly", "guided", "python"],  // assembly/guided — после их появления
  "promote": { "distinctTasks": 2, "maxFailedBefore": 2, "window": 5 },
  "support": { "consecutiveFailures": 3 },
  "transfer": { "afterBlocksSuccess": true }
}
```

| Правило | Условие | Действие | Почему так |
|---|---|---|---|
| **Повышение самостоятельности** | По навыку N в режиме M приняты ≥ 2 **разных** задания, в каждом не больше 2 неудач до успеха (в окне последних 5) | Предложить следующий разрешённый режим для заданий с навыком N | Два разных задания — минимальный сигнал переноса, а не запоминания. Это гипотеза |
| **Дополнительная помощь** | 3 неудачи подряд по одному заданию | Предложить по очереди: (1) подсказку, (2) теорию задания, (3) визуальный режим, если он разрешён | Помощь от лёгкой к сильной. Блоки — не наказание, а инструмент |
| **Перенос в Python** | Задание с навыком N принято в `blocks` или `mixed` | Предложить следующее задание с тем же навыком в Python | Похожая, но **не та же** задача. Перенос готового кода из блоков запрещён (ADAPTIVE_TASK_SCHEMA.md §2.3) |
| **Ручное назначение** | Учитель задал режимы ученику | Рекомендации не выходят за заданное | Контроль учителя |

«Следующее задание с тем же навыком» берётся только из уже выданных группе заданий. Kodik не создаёт задания сам. Если такого задания нет, рекомендация адресуется учителю: «Для переноса в Python по теме «Условия» нет задания».

## 4. Модель освоения (отображение)

| Навык | Блоки | Блоки + Python | Python |
|---|---|---|---|
| Переменные | Освоено | Освоено | В процессе |
| Условия | В процессе | — | Ещё не подтверждено |

Значения ячейки:
- «Ещё не подтверждено» — нет принятых заданий;
- «В процессе» — есть попытки, порог не достигнут;
- «Освоено» — порог из правила повышения.

Это **описание наблюдаемого**, а не оценка ученика. Ученик видит только свою таблицу, публичных рейтингов нет.

## 5. Ручное управление преподавателя

| Возможность | Где хранится |
|---|---|
| Стартовый режим группы | `assignments.mode_policy.start` |
| Свободное переключение / только с разрешения / зафиксировано | `mode_policy.switching` |
| Режим конкретному ученику | `student_mode_overrides` |
| Выключить рекомендации | `mode_policy.recommendations` |
| Почему рекомендовано | `mode_events.reason`: правило, навык, задания-основания |
| Вернуть доступ к блокам | Изменение override или политики, с аудитом |

## 6. Что проверяем с преподавателем — Открыто

1. Порог «2 разных задания» — достаточно ли? Нужно ли окно по времени?
2. Порядок «сборка кода» перед «код с подсказкой» (ADAPTIVE_LEARNING_ARCHITECTURE.md §3).
3. Кто видит рекомендацию первым — ученик или учитель («рекомендует — учитель подтверждает»)? По умолчанию для пилота предлагается **учитель подтверждает**.
4. Нужен ли серверный учёт подсказок для правил.

## 7. Данные и несовершеннолетние

Храним только:
- попытки (уже есть);
- режим попытки;
- события рекомендаций и переходов — без времени на экране, движений и кликов.

Срок хранения и состав данных согласуются со школой вместе с общими правилами обработки персональных данных (PILOT_READINESS_CHECKLIST.md).
