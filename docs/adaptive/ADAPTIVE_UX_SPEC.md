# UX адаптивных заданий: конструктор, ученик, преподаватель

Основа — согласованный конструктор и дизайн-система (`docs/design/`, скриншоты `03`–`06`, `08`–`11`). Технический интерфейс PoC (`docs/design/screenshots/adaptive/`) показывает механику, а не финальный дизайн.

Статусы: **PoC** — механика доказана; **План** — спроектировано; **Открыто** — решить с дизайнером или владельцем.

## 1. Конструктор: раздел «Путь обучения» — План

Название раздела — «Путь обучения» (альтернатива «Режимы обучения»). **Открыто:** выбрать с UX/UI-дизайнером.

### Где раздел находится

Быстрое создание не меняется: пять разделов, как на `03-builder-quick.png`.

«Путь обучения» — **первая группа в «Расширенных настройках»**. Её сводка видна в оглавлении слева без раскрытия:
- «Блоки, Блоки + Python, Python»;
- «Только Python»;
- «Блоки недоступны: …».

Простое Python-задание учитель создаёт ровно как сейчас: раздел не нужно открывать. Выключить блоки можно одним переключателем.

### Что Kodik делает сам

После того как в разделе 2 заполнен эталон, Kodik без лишних кликов:
1. разбирает эталон (`analyzeReference`) — PoC;
2. если задача совместима, включает режимы «Блоки», «Блоки + Python», «Python» и собирает палитру из блоков эталона — PoC;
3. предлагает навыки чипами «Ввод · Переменные · Арифметика · Вывод». Над ними подпись: «Kodik определил по эталону — проверьте». План;
4. если несовместима — сводка «Только Python». В разделе одна строка с причиной: «Цикл со счётчиком, который используется внутри, пока не имеет блока. Задание останется в режиме Python». PoC (тексты причин).

### Содержимое раздела

| Блок | Элементы | Умолчание |
|---|---|---|
| Режимы | Три переключателя: «Блоки», «Блоки + Python», «Python» (Python нельзя выключить) | Все совместимые включены |
| Навыки | Чипы с крестиком, «+ Навык» из списка | Из анализа эталона |
| Палитра блоков | По категориям, как в PoC. Блоки эталона отмечены «нужен для решения». Снять такой блок нельзя без предупреждения «Без этого блока задачу нельзя решить» | Ровно блоки эталона |
| Стартовое поле | «Пустое поле» / «Собрать стартовые блоки» (тот же редактор). Предупреждение, если стартовые блоки уже проходят тесты | Пустое |
| Подсказки | Общие подсказки задания (уже есть) | — |
| Переходы | Ссылка «Настраивается при выдаче группе» | — |

Принцип «строительные элементы, а не решение»: палитра — это **типы** блоков. Готовая программа на поле не появляется.

### Предпросмотр

Существующая правая панель получает переключатель **Блоки / Блоки + Python / Python**. Используются те же компоненты, что у ученика. Запуски автора не создают попыток (как сейчас). PoC: переключение и сохранение блоков между режимами.

### Проверка качества

Проверка остаётся по Python (эталон и типичные ошибки). Добавляется строка чек-листа: «Режим блоков: палитра покрывает решение ✓». Изменение палитры сбрасывает подтверждение (ADAPTIVE_TASK_SCHEMA.md §2.1).

## 2. Ученик — PoC (механика), План (дизайн)

Трёхчастная среда (`08-student-workspace.png`) сохраняется: условие слева, рабочая область справа, консоль и результаты снизу.

| Режим | Рабочая область | Ширина ≥ 1280 | 1024–1279 |
|---|---|---|---|
| Блоки | Поле Blockly с палитрой задания | Полная ширина справа | Так же |
| Блоки + Python | Blockly и Python-зеркало рядом (60/40, разделитель перетаскивается) | Рядом | Вкладки «Блоки | Python» над областью, оба представления доступны |
| Python | Существующий редактор | — | — |

- **Индикатор режима.** Сегментный переключатель над рабочей областью: «Блоки · Блоки + Python · Python». Видны только разрешённые режимы. Недоступный режим не показывается вовсе.
- **Переход между режимами.** Без подтверждения, работа не теряется: блоки общие для двух визуальных режимов, у Python свой черновик. При первом переходе в Python одна строка: «Здесь ты пишешь код сам. Блоки сохранятся — можно вернуться». PoC: блоки переживают переключение; найдена и исправлена ошибка, когда уничтожение поля затирало черновик.
- **Зеркало.** Заголовок «Python из твоих блоков». Выбор блока подсвечивает его строки (PoC). Ошибки трансляции — ссылки, которые выделяют проблемный блок (PoC).
- **Кнопки.** «Запустить», «Проверить решение», «Подсказки» — на тех же местах во всех режимах.
- **Результат проверки** — тот же компонент. Подпись режима: «Решено в режиме: Блоки».

### Тексты рекомендаций

| Ситуация | Текст | Кнопки |
|---|---|---|
| Уверенно в блоках | «Ты уверенно собираешь программы с переменными. Попробуешь написать такую же на Python?» | «Попробовать» · «Позже» |
| Три неудачи подряд в Python | «Попробуй ещё раз с визуальной подсказкой: собери программу из блоков и посмотри, какой получится код.» | «Открыть блоки» · «Продолжу в Python» |
| После успеха в блоках | «Следующее задание похоже на это, но решается на Python.» | «Перейти» |

Запрещено:
- «ты плохо справился», «возвращаем тебя к блокам»;
- сравнение с другими учениками;
- смена режима без нажатия ученика.

| Где | Что |

| Рекомендации | Список «Kodik рекомендует: Миша — Python для переменных (2 задания без подсказок)». Кнопки «Подтвердить» · «Не сейчас» |

## 4. Десктоп

Проверено на PoC: 0 px переполнения на 1024 CSS px при смешанном режиме (`07-mixed-1024.png`). Финальный дизайн обязан поддерживать 1024, 1280 × 800, 1366 × 768, 1440 × 900 и 1920 × 1080. Размеры панелей запоминаются в `localStorage`.

## 5. Открытые вопросы для дизайнера

1. Название раздела: «Путь обучения» или «Режимы обучения».
2. Цвета категорий блоков. В B2C они свои (фиолетовые переменные и т. п.), дизайн-система B2B их не определяет. Предложение — приглушённые оттенки бренда с контрастом текста ≥ 4,5:1.
3. Как показывать режим в матрице, не перегружая её.
