# Надёжность первого этапа платного пилота

Полная цель из 28 пунктов остаётся активной. Этот документ фиксирует завершённые технические проверки первого этапа, а не разрешение продавать продукт как полностью готовый.

Первые продажи планируются в Беларуси. Владелец подтвердил наличие преподавателя для будущего наблюдения. Сеанс с ним и проверки с детьми ещё не проводились; их нельзя подменять тестами разработчика.

## Сохранение

Черновики задания принимаются без названия и инструкции. Публикация отдельно проверяет обязательные поля и конфигурацию тестов. Автосохранение использует серверную ревизию, локальный буфер принадлежит конкретным организации и аккаунту. Потеря связи сохраняет буфер; переход и повторный вход восстанавливают его только владельцу. При конфликте сервер хранит обе правки и возвращает текущую версию для сравнения.

Черновики ученика также имеют ревизии; чужая вкладка не может незаметно перезаписать код. Неподтверждённая отправка хранит уникальный ключ: повтор запроса или обновление страницы возвращает ту же проверку. Преподаватель получает свежий журнал при входе в раздел, фокусе вкладки и каждые пять секунд, видит время последнего обновления и ручную кнопку.

Проверки: `tests/pilot-foundations.mjs`, `tests/pilot.e2e.ts`, расширенный `tests/b2b.e2e.ts` с отдельным кабинетом преподавателя. Отдельно проверены конфликт двух преподавателей, offline-переходы, смена пароля с отзывом сессии, восстановление под тем же учеником и отсутствие чужого черновика у второго ученика, потерянный ответ уже принятой отправки.

## Очередь и авария

Сервер сохраняет принятые проверки в SQLite. Состояния: queued, running, completed, cancelled. При старте незавершённая работа возвращается в очередь. Попытка и завершение проверки фиксируются одной транзакцией; идентификатор попытки совпадает с заданием очереди, повтор не создаёт новую оценку.

Предел: четыре активных процесса, 240 ожидающих проверок, до 120 на школу и до трёх на ученика. Очередь переключается между школами. Ожидание пробных запусков ограничено; отмена доступна для ещё не начатой проверки. Защита входа учитывает и логин, и сеть, чтобы класс за одним IP не исчерпывал лимит 30 входов.

`tests/pilot-crash.mjs` аварийно завершает отдельный процесс сервера при наличии незаконченных проверок, запускает его на той же базе и проверяет ровно один результат для каждого принятого запроса. Проверено 12 принятых решений.

## Локальная нагрузка

Windows 10.0.26200, AMD Ryzen 7 260, 16 логических процессоров, около 15 ГиБ RAM, Node 24.19.0, локальная SQLite WAL. Учебный интерпретатор: четыре процесса, два теста на решение. 60 входов одновременно через один адрес прошли примерно за 0,8 секунды.

Один класс из 30 учеников: все 30 решений приняты и проверены, около 2 секунд на всю группу. Две параллельные группы по 30: все 60 решений проверены, около 4,3 секунды; p95 около 4,1 секунды. Технических отказов нет. Измерения повторно получаются `node --test tests/pilot-load.mjs`, полный отчёт — `work/pilot-load-report.json`.

Это лабораторный профиль текущего компьютера. Он не доказывает производительность будущего сервера, долгой эксплуатации или произвольных программ с максимальными лимитами. Перед размещённым пилотом нужен повтор на выбранном оборудовании.

## Python и экран ученика

70 доверенных примеров сравниваются с закреплённым CPython 3.11.9 (`tests/python.compatibility.ts`). Исправлены тип float при выводе и передаче через переменные/функции/списки, цепочки сравнений с однократным вычислением, локальные переменные функций, комментарии, строковые escapes и представление списков. Добавлены целочисленное деление, ограниченные конкатенация и повторение списков/строк; float запрещён там, где Python требует целый индекс или range. Вывод с переводами строк и подсказка input сохраняют порядок. Вложенные функции и переопределение встроенных команд явно отклоняются как неподдерживаемое подмножество. CPython запускается только для фиксированных примеров тестов; пользовательский код по-прежнему исполняет отдельный учебный интерпретатор. Эти проверки не являются доказательством полной совместимости Python.

Экран практики имеет отдельные прокрутки условия, редактора и консоли. Действия находятся в собственной видимой строке; код — от 16 px с регулировкой. Разделитель меняет ширину панелей мышью или клавиатурой, навигация сворачивается. Проверены 1280×720, 1366×768, 1440×900, 1920×1080 и уменьшенная эффективная область 1093×614. Длинный код и сообщение об ошибке не перекрывают запуск и проверку. Настоящая проверка школьного ноутбука с участниками ещё предстоит.

## Версии и назначения

Миграция 6 добавляет task_versions с запретом изменения/удаления на уровне базы. Преподаватель редактирует текущий черновик без отключения урока у группы; публикация фиксирует его ревизию. Назначение ссылается на опубликованную версию. Новая публикация и снятие из каталога не меняют уже назначенное задание.

Повторное назначение тому же классу или назначение второй группе создаёт отдельное прохождение: маршрут, серверный и локальный черновики, попытки и ключ отправки относятся к assignment_id. При неоднозначном старом маршруте ученик выбирает назначение через свои курсы; API требует конкретное назначение. Законченный курс показывает завершение вместо повторного открытия первого задания. Снятие назначения архивирует его, сохраняя историю. Старые попытки и принятые задания очереди сохраняют исходные snapshot и ключи; невосстановимые связи остаются legacy. Старый черновик переносится лишь при однозначной группе, исходные данные сохраняются.

Оба API отправки используют одну долговечную очередь и обязательный request_key. Проверки: tests/assignment-versions.mjs, обновлённая прежняя интеграция и браузерный сценарий повторного назначения. Версии целых уроков, массовые прохождения и журнал группы ещё не реализованы.

Перед миграцией 6 создана work/backups/pre-assignment-versions.sqlite; восстановление в verified-restore-versions.sqlite сохранило все три исходные записи в 16 таблицах и подтвердило HTTP readiness. Отдельная историческая фикстура проверяет сохранение старых назначений, неоднозначных черновиков и snapshot. Рабочая база обновлена до схемы 6.

## Данные и запуск

Миграции выполняются последовательно и транзакционно (версии 1–6). Более новая неизвестная схема отклоняется без понижения. Добавлено резервное копирование через SQLite backup API с проверкой целостности и пробное восстановление с запуском HTTP-сервера и сравнением существующих записей.

База текущего проекта версии 1 была сохранена в `work/backups/pre-pilot-foundations.sqlite`. Её отдельная восстановленная копия успешно открылась на версии 5: 12 исходных таблиц, все три существующие записи сохранены, HTTP readiness успешен. Рабочая база обновляется миграциями, не пересоздаётся.

В production запуск требует точного HTTPS `KODIK_ORIGIN` и абсолютного пути `KODIK_DB` на постоянном диске. SIGTERM/SIGINT ожидают активные проверки; ожидающие остаются в базе. Readiness проверяет базу и наличие сборки исполнителя. Диагностика API не печатает тексты решений и реквизиты пользователей.

GitHub workflow `.github/workflows/critical.yml` запускает `npm run check:critical` при push/PR. Workflow добавлен локально; запуск в GitHub пока не утверждается.
