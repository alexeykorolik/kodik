# Kodik Schools — desktop B2B

Подготовка к платным пилотам продолжается. Текущее состояние по 26 требованиям повторного аудита 19 октября: PILOT_READINESS.md. История технической основы: docs/PILOT_FOUNDATIONS.md. Исправление основного маршрута, порядка и выдачи: docs/ASSIGNMENT_OPERATIONS.md.

Образовательное пространство для компьютерных школ. Преподаватель создаёт курс и Python-задания, назначает их группам и видит реальные попытки учеников. AI временно отключён безусловно, включая прежний API.

## Быстрый запуск

Нужен Node.js **24.19.x** (встроенный `node:sqlite`). Команды выполняются в `D:/projects/kodik`:

```powershell
npm ci
npm run build
npm start
```

Открыть http://127.0.0.1:4173. Кнопка «Открываете школу?» создаёт новую организацию и администратора. Сохраните выданный recovery-код. Реальные секреты в репозитории не нужны; Supabase, AI-ключи и Docker для этого пилота не требуются.

`npm run local` собирает и запускает сервер одной командой. Остановить — Ctrl+C. Для разработки запустите `npm start` и во втором терминале `npm run dev`; Vite передаёт `/api` локальному серверу 4173.

Актуальный шаблон переменных школьного сервера — .env.example. npm start читает окружение процесса, а не загружает этот файл автоматически. Для production обязательны NODE_ENV=production, точный HTTPS KODIK_ORIGIN и абсолютный KODIK_DB на постоянном диске; задайте их в конфигурации службы или терминале. Настройки прежнего отдельного курса вынесены в docs/legacy.env.example. AI-ключи для запуска не нужны.

## Первый учебный сценарий

1. Создайте школу и сохраните код восстановления администратора.
2. В «Участниках» создайте преподавателя и ученика. Достаточно псевдонима, уникального логина и пароля от 10 символов. Передайте данные участникам лично.
3. Войдите преподавателем. Создайте курс, модуль и урок.
4. Добавьте задание. Заполните шаги конструктора: название, содержание, стартовый код, проверка, предпросмотр, публикация.
5. Пример: инструкция «Выведи Привет, мир!», ожидаемый вывод `Привет, мир!`, закрытый эталон `print("Привет, мир!")` и неправильный пример `print("Привет")`. На шаге «Проверка» сохраните и проверьте эталон/неправильные примеры. Для ручной работы задайте и подтвердите критерии.
6. В «Учебных группах» создайте группу, добавьте ученика и назначьте опубликованное задание.
7. Войдите учеником, откройте курс, выполните задание и нажмите «Проверить решение». После обновления сохраняются код и история.
8. Войдите преподавателем и откройте «Результаты». Там видны прогресс, попытки, решения и задания на ручной проверке.

Администратор может совмещать работу преподавателя. Опубликованное задание можно редактировать: изменения сохраняются в черновик, а публикация создаёт новую неизменяемую версию для будущих назначений. Уже назначенные работы сохраняют прежнее содержание. Копии заданий и курсов создаются черновиками. Логины пока уникальны для всей платформы.

Выдача задания защищена от повторов запроса и потери ответа. После восстановления страницы повторная проверка выдачи возвращает прежнее назначение. Для самостоятельного нового прохождения используйте «Назначить повторно». Кнопка «Срок» меняет дату существующей работы, сохраняя её черновики и попытки. Продолжение курса учитывает зафиксированный порядок модулей, уроков и заданий, а не время их выдачи.

В начале конструктора есть семь готовых шаблонов. Предпросмотр использует общий экран ученика; пробный пример сохраняется отдельно от стартового кода и эталона. Новые публикации требуют подтверждения именно текущей ревизии. История позволяет повторить проверку старой ревизии, не подменяя текущий черновик. Старые выданные работы сохраняют доступ; для новой выдачи прежних непроверенных снимков нужна проверка и перепубликация. Детали — docs/TASK_QUALITY.md.

## Полное занятие и выдача программы

На странице курса нажмите «Сценарий урока». Добавьте цель, объяснение, пример кода, практику, вопрос, итоговую работу и итог. Сначала подготовьте и опубликуйте отдельные практические задания этого урока. Заметки преподавателя и правильные ответы закрыты от учеников. Публикация урока фиксирует порядок и версии практики.

В группе выберите «Выдать учебную программу»: можно выдать курс, модуль, урок или подборку. Проверьте состав, группу, версии и срок, затем подтвердите выдачу. Первое занятие откроется сразу. Дальше преподаватель открывает занятия через программу группы и действие «Провести занятие»; там же виден журнал шагов. Новых участников подключайте к уже выданной программе явно, с начала либо с текущего занятия. Результаты и предыдущие версии при повторении сохраняются. Подробности и ограничения — docs/COMPOSED_LESSONS.md. Готовой стартовой программы из 6–8 занятий пока нет.

## Демонстрационные данные

```powershell
npm run demo:b2b
```

Создаёт отдельную демонстрационную школу, преподавателя, ученика, курс, группу и три назначенных задания в настоящей базе. Логины, случайный пароль и recovery-код выводятся один раз в терминал. Не сохраняйте их в Git. Каждый запуск создаёт новую демонстрационную школу. Результаты остаются пустыми до реальных попыток.

## Хранение и восстановление

База находится в `data/kodik.sqlite`, путь можно переопределить переменной `KODIK_DB`. Каталог исключён из Git. Для простой резервной копии остановите сервер и скопируйте каталог `data` целиком; восстановление — при остановленном сервере вернуть сохранённый каталог. Никогда не удаляйте базу при обновлении приложения. Схема обновляется последовательными транзакционными миграциями; более новая неизвестная версия отклоняется без понижения.

Пароли хранятся как scrypt с солью. Сессии — HttpOnly cookies, в базе хеши токенов. Сброс пароля и отключение аккаунта отзывают все сессии. Ученик восстанавливает доступ через преподавателя; администратор — через одноразовый recovery-код на странице входа. После восстановления выдаётся новый код.

## Проверка Python

Повторно используется учебное подмножество Python из Kodik: print, input, int, str, len для списков, range, переменные, списки, условия, циклы и функции. Отступ — 4 пробела. Это **не полный CPython**. Импорты, классы, внешние библиотеки, сеть и файловая система не поддерживаются.

Программы разбираются собственным парсером в отдельном процессе с Node permissions, 48 МБ heap, дедлайном 2,5 секунды, лимитом 10 000 операций и ограниченным выводом. Одновременно не более четырёх процессов. Принятые проверки сохраняются в SQLite и ожидают очередь с чередованием школ; повтор отправки не создаёт новую попытку. Пользовательский текст никогда не передаётся `eval`, shell или системному Python. Node permissions служит дополнительной защитой; безопасность языка опирается на ограниченный парсер/интерпретатор.

При автопроверке завершающие пробелы и переносы вывода игнорируются. Для каждого теста ввод задаётся отдельными строками. Скрытые входы, ожидаемые ответы и вывод скрытых тестов не выдаются ученику. При ручной проверке код сохраняется для преподавателя. Ошибка сервиса проверки не считается успешным решением.

## Развёртывание пилота

Один Node-процесс с постоянным локальным диском; корень запуска — папка проекта. Сначала `npm ci` и `npm run build`, затем `npm start` под менеджером процессов. Сборка включает отдельный `.runner/runner.cjs`, который нужен серверу вместе с `dist` и `server/b2b`.

Переменные:

- `PORT` — по умолчанию 4173.
- `HOST` — по умолчанию 127.0.0.1. За обратным прокси оставьте loopback.
- `KODIK_DB` — постоянный путь к базе; в production обязателен абсолютный путь.
- `NODE_ENV=production` — включает Secure cookie; нужен HTTPS.
- `KODIK_ORIGIN=https://school.example` — точный внешний адрес для проверки Origin за HTTPS-прокси. В production задайте обязательно.

Не размещайте SQLite на сетевом диске и не подключайте несколько реплик к одному файлу. Для массового SaaS потребуются PostgreSQL, общие лимиты/очередь и отдельный контейнерный исполнитель полного Python. Перед пилотом настройте резервные копии, доступы и правила хранения данных детей. Сервис не отправляет письма и не собирает email.

## Резервная копия и пробное восстановление

```powershell
node scripts/database-backup.mjs data/kodik.sqlite work/backups/backup-NEW.sqlite
node scripts/verify-backup.mjs work/backups/backup-NEW.sqlite work/backups/restore-NEW.sqlite
```

Всегда выбирайте новые имена: существующие файлы не перезаписываются. Проба запускает отдельный локальный сервер на восстановленной копии, проверяет готовность и сохранность исходных записей. Рабочую базу не заменяет. Для фактического восстановления остановите основной сервер, назначьте восстановленный файл через KODIK_DB и запустите сервер. Сначала сохраните повреждённую базу для разбора. Не копируйте один основной файл SQLite в момент работы с WAL вместо backup API.

Тесты совместимости Python требуют CPython 3.11.9 только как доверенный эталон. Сам учебный сервер не запускает Python, установленный в ОС.
