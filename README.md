# Kodik Schools — настольная школьная платформа

Локальный маршрут управляемого пилота: владелец подключает компанию и лицензию, администратор создаёт класс, преподаватель выдаёт программу и проводит занятия, дети решают общие задания блоками, в смешанном режиме или на Python. AI отключён.

Состояние требований: [PILOT_READINESS.md](PILOT_READINESS.md). Инструкция для владельца, администратора и преподавателя: [docs/PILOT_OPERATOR_GUIDE.md](docs/PILOT_OPERATOR_GUIDE.md).

## Запуск

Нужен Node.js 24.19.x. Из папки проекта:

```powershell
npm ci
npm run build
npm start
```

Приложение: http://127.0.0.1:4173. `npm run local` собирает и запускает его одной командой. Остановить — Ctrl+C.

Самостоятельная регистрация создаёт администратора и школу с пробной лицензией на 14 дней и 60 активных учеников. Сохраните одноразовый код восстановления. Для подключения компаний владельцем сначала создайте отдельный аккаунт командой `node scripts/provision-owner.mjs`: логин и пароль берутся из `KODIK_OWNER_LOGIN` и `KODIK_OWNER_PASSWORD`. Полный порядок — в инструкции оператора. Реальные секреты и пароли в репозитории не хранятся.

Для разработки запустите `npm start` и `npm run dev` в разных терминалах. Настройки — в `.env.example`; сервер читает окружение процесса, файл автоматически не загружает.

## Первый класс

1. Администратор создаёт группу. В «Управлении школой» проверяет и импортирует список `Имя; логин`; пароли показываются один раз.
2. Назначает группе основного и при необходимости совместного преподавателя. Общая роль учителя не даёт доступа ко всем детям школы.
3. В «Курсах» готовит стартовую программу из шести занятий. Все 12 практик имеют проверенные Python- и блоковые образцы.
4. В группе выдаёт программу через предпросмотр. Преподаватель открывает занятия и смотрит матрицу шагов и запросы помощи.
5. Ученик проходит объяснение, пример, практику, вопрос, другую задачу и итог. Блоковая и текстовая работы сохраняются отдельно.
6. В «Способах решения» преподаватель меняет разрешения. Предложение перехода принимает сам ребёнок; открытая работа не переключается автоматически.
7. В «Журнале и проверке» доступны работы, ручная оценка с историей, фильтры, страницы и экспорт.
8. Владелец ведёт карточку компании, срок лицензии и следующее коммерческое действие.

Конструктор сохраняет неполные черновики. Режимы, палитра, стартовые блоки и закрытый блоковый образец редактируются во вкладке редактора. Новая публикация требует подтверждённой проверки текущей ревизии. Предпросмотр использует общее рабочее место ученика и не создаёт его попыток.

Выданные версии неизменяемы. Повторное назначение — отдельное прохождение. Повтор запроса не создаёт второе назначение или результат. Смена сроков, архивирование, истечение лицензии и обновление сохраняют историю. Поздних участников включают в уже выданную программу явно.

## Проверки и восстановление

```powershell
npm run check:critical
node scripts/database-backup.mjs SOURCE.sqlite NEW_BACKUP.sqlite
node scripts/verify-backup.mjs BACKUP.sqlite NEW_RESTORE_PROBE.sqlite
```

Обязательный набор включает сборку, прежние smoke-проверки, настоящий HTTP API, Blockly, обязательную сверку с CPython 3.11, браузерные маршруты и локальную нагрузку. Отсутствие CPython — ошибка проверки. Локальная нагрузка измеряет 30 и 60 учеников, а также смесь работ 60 учеников из трёх школ. Отчёты сохраняются в `work/`.

`node scripts/verify-clean-release.mjs` проверяет чистую установку из зафиксированных Git-исходников: зависимости, сборку и smoke-проверки. Архив исходников и отдельная проверочная копия остаются в `work/`.

Для production нужны HTTPS, точный `KODIK_ORIGIN`, абсолютный `KODIK_DB` на постоянном диске, служба запуска, сбор ошибок и резервные копии. Поддерживается один экземпляр с SQLite. Перед обновлением требуется проверенная копия; несовместимая проверяющая среда требует явного посредством `scripts/reverify-published.mjs` согласно `docs/adaptive/MODE_MODEL.md` и скрипту повторной проверки.

## Границы готовности

Целевого сервера и доступа к преподавателю с детьми пока нет. Проверка другого окружения, раннее наблюдение конструктора и наблюдение полноценного занятия не проведены. Автотесты подтверждают маршруты и ограничения, но не удобство для детей и не перенос навыков. Полную коммерческую готовность пока не заявляем.

Исполняется учебное подмножество Python: без импортов, файлов, сети, классов и внешних пакетов. Лимиты времени, памяти, вывода и операций обязательны. Переходы предлагаются прозрачными правилами; выводы не объявляют навык освоенным или работу выполненной без помощи.

Исходный самостоятельный курс доступен по `?legacy=1`; его прогресс отделён от школьного. Историческая документация: `docs/PILOT_FOUNDATIONS.md`, `docs/COMPOSED_LESSONS.md`, `docs/TASK_QUALITY.md`, `docs/LEARNING_RULES.md`, `docs/adaptive/MODE_MODEL.md`.
